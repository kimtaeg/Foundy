## 1. 한 줄 정의

**어디에서 사업을 할지 이미 정한** 카페·음식점 청년 창업가를 위한 **창업 전 사전 점검 에이전트**.
로그인 후 업종·주류 판매 여부·주소(층)·가게 이름·개업 예정일을 한 번 입력하면 건축물대장·법령·상표를 조회해
"계약 전 꼭 확인 / 개업 전 할 일 / 운영 중 주의" 리포트와 개업 역산 체크리스트를 만들고, 주변 상권도 함께 분석한다.
문제가 나온 항목은 판정만 던지지 않고 **결과 카드**(결론·선택지·추천·대신 만든 결과물·사용자가 할 일 1개)로 보여줘서, 사용자는 결정 한 번으로 시작해 **실행 → 완료**까지 이어가고, 완료하면 **다음으로 할 일**이 자동으로 정리된다.

### 결과 카드 (문제 항목의 표시 형식)

| 칸 | 내용 |
|----|------|
| 결론 | 한 줄, 결과 중심의 쉬운 말 |
| 안 하면 생기는 일 | 돈·시간 기준 |
| 선택지 | 대응 방안 비교 (기간·금액은 근거가 있을 때만 숫자, 없으면 "확인 필요"). 고르면 바뀌는 내용을 미리 보여준다 |
| 추천 | 기본 선택 하나와 이유. `[추천대로 진행]` 한 번으로 가게 정보·체크리스트 반영 |
| 대신 만든 결과물 | 구청 문의 문구(전화·민원용)와 **기관 전화번호**, 임대차 특약 문구, 열람 링크, 신고서류 초안 |
| 당신이 할 일 | 1개와 소요 시간 (결정·서명·방문·전화) |
| 진행 | **결정 → 실행("문의했어요") → 완료**, 선택은 언제든 되돌릴 수 있다 |
| 다음으로 할 일 | 실행·완료 직후 카드 안에 자동 정리 (새로 생긴 할 일 → 결정 대기 → 다른 카드의 직접 할 일 → 가까운 체크리스트). 알림에도 남는다 |
| 체크리스트 연동 | 같은 일인 체크리스트 항목은 카드를 완료하면 자동 체크 (카드가 둘 이상 연결된 항목은 모두 완료해야) |

## 2. 대상 사용자

- 카페·음식점을 처음 여는 청년(39세 이하) 창업가 중 **자리(주소)를 이미 정한 사람**. 계약 전이거나 계약 직후이고, 어떤 확인이 필요한지 몰라 묻지도 못한다.
- 입지를 아직 정하지 못한 사람을 위한 입지 추천·후보 비교는 대상이 아니다 (판단 위험이 커서 범위 밖).
- 시연 인물: 이서연(29세, 성수동 1층 상가, 카페 '모노커피', 개업 내년 3월).

## 3. 입력

| 항목 | 필수 | 비고 |
|------|------|------|
| 소셜 로그인 | O | 카카오·Google·네이버. 가입 없이 둘러보는 **예시 계정** 제공 |
| 업종 | O | MVP는 카페·음식점만 |
| 주류 판매 여부 | O | 휴게/일반음식점 결정에 사용 (되묻기) |
| 주소(층) | O | 도로명주소 → 건축물대장 조회. 입지를 정한 주소 |
| 가게 이름 | O | 상표 유사성 검색 |
| 개업 예정일 | O | 역산 일정표 기준일 |
| 메뉴·광고 문구 | | 효능 표현 등 위반 소지 점검 |
| 출생 연도 | | 지원사업 자격 판정에만 사용 |
| 테라스·직원·준비 자금 | | 되묻기. 옥외영업·고용 카테고리·지원사업 계산에 사용 |

첫 설정 이후의 수정은 **마이페이지**에서 한다. 사업 정보를 바꾸면 영향받는 점검만 다시 반영하고, 영향받는 카드의 이미 고른 선택은 초기화한다 (바꾸기 전에 미리 보여준다).

## 4. 기능 범위

### Must

- [ ] 소셜 로그인과 계정별 데이터 분리, 예시 계정(가입 없이 시연)
- [ ] 첫 설정(가게 등록) + 되묻기, 조사 중 진행 화면(SSE, `fallback` 표시)
- [ ] 마이페이지: 가게 정보·영업 조건 수정, 영향 미리보기, 영향받는 점검만 다시 반영, 변경 기록
- [ ] 점검 리포트: 건물 용도·위반건축물·상표·영업신고 서류·메뉴 광고 문구, 판정 3단계, 근거(출처·조회일자·링크)
- [ ] 결과 카드: 선택지·추천·대신 만든 결과물·기관 전화번호·할 일 1개, 결정 → 실행 → 완료, 되돌리기
- [ ] 다음으로 할 일 자동 정리와 알림 기록, 점검 카드 완료 → 체크리스트 자동 체크
- [ ] 개업 체크리스트: 시기별·카테고리별·달력, 개업일 역산, 서류 초안
- [ ] 내 가게 홈(결정할 것·직접 할 일·다음 할 일)과 알림 센터(유형 탭·액션 버튼)

### Should

- [ ] 상권 분석: 정한 주소 주변 동종 업소 지도(카카오 CE7·FD6), 상권 요약, 경쟁 강도
- [ ] 지원사업: AI 자격 판정, 포스터 카드, 필터·정렬·보기 전환
- [ ] AI 상담: 근거 칩, 확인 후 적용 제안, 항목별 상담, 통화 준비 도우미
- [ ] 체크리스트 `.ics` 내보내기

### Could

- [ ] 상권 분석의 가격 포지셔닝과 "이 자리에서 눈여겨볼 점"(규칙 생성), 계약 전 현장 확인 목록 (가격 분포는 예시 데이터)
- [ ] 알림 센터 "시점 이동" 시연(개업 D-7·6개월 후, 예시 배지)
- [ ] 다시 조회 → 바뀐 것만 알림 (수동 버튼)
- [ ] 상담의 "오늘 뭐부터 하죠?", 추천 질문

### 범위 변경 (2026-11-19): 입지를 정한 사용자만 대상, 로그인 추가

- 입지를 아직 정하지 못한 사용자를 위한 기능(지역별 후보 상권 비교, 입지 먼저 추천)은 만들지 않는다. 입지 선택은 판단 위험이 커서 이 서비스의 범위 밖이다. 사용자는 **어디에서 사업을 할지 정한 사람**이고, 주소를 입력하면 점검 리포트와 상권 분석을 함께 보여준다.
- 상권 분석은 정한 자리 주변을 분석하는 기능이다. 지도 마커와 동종 업소 수는 카카오 카테고리 검색(CE7 카페, FD6 음식점, 한 번에 최대 45건)으로 실제 연결하고, 경쟁 강도·프랜차이즈 비율은 조회 데이터에서 규칙으로 계산한다. 폐업 추이·유동인구·평균 임대료·메뉴 가격은 데이터가 없으면 "데이터 없음", 화면 시연이 필요하면 [예시] 배지를 붙인다.
- 후보 자리 직접 입력(보증금·월세)과 후보 비교는 만들지 않는다. 건물 용도가 맞지 않으면 결과 카드의 "다른 자리를 알아보기" 선택지로 안내하고, 새 주소는 마이페이지에서 바꾼다.
- **로그인을 범위에 넣는다** (사용자별 데이터 보관). 이전 "범위 밖: 로그인"을 대체한다. 마감이 가까워 일정 위험이 커졌으므로, 실제 소셜 로그인 연결이 늦으면 시연용 계정으로 두고 **예시 계정은 항상 열어 둔다**. `CLAUDE.md`의 "로그인은 범위 밖" 규칙도 이에 맞게 고쳐야 한다.

### 범위 밖 (예선 이후)

- 입지 추천, 지역별 후보 상권 비교, 후보 자리·매물 비교
- 대출 안내
- 카페·음식점 외 업종
- 예약 자동 재조회, 상권 모니터링, 폐업·양도 안내 (로드맵)

## 5. 데모 시나리오

| # | 입력 | 기대 결과 |
|---|------|-----------|
| S1 | 휴게음식점 용도 층 + 주류 판매 | `위반 소지 높음`: 일반음식점 필요, 건물 용도 불일치. 결과 카드: 선택지(술 빼고 시작 / 용도변경 신청 / 다른 자리를 알아보기), 추천, 구청 문의 문구·기관 전화번호·특약 문구, 할 일 1개. 실행 → 완료하면 다음으로 할 일 정리와 체크리스트(건물 확인) 자동 체크(위반건축물 카드까지 완료 시) |
| S2 | 등록 상표와 비슷한 가게 이름 | `확인 권장`: 유사 상표 목록. 결과 카드: 이름 바꾸기(겹치지 않는 후보) / 그대로 진행 선택지와 추천. 이름 바꾸기를 고르면 가게 이름과 상표 점검 결과가 바뀐다 |
| S3 | 메뉴 설명에 효능 표현 | `확인 권장`: 광고 문구 위반 소지. 결과 카드: 문구 수정안 선택지, 수정 제안 초안, 체크리스트에 메뉴판 문구 반영 항목 추가 |
| S4 | 문제없는 입력 | 위반 항목 없이 할 일과 일정표만 표시. 결과 카드 없음 |
| S5 | 마이페이지에서 주소·술 판매 변경 | 저장 전에 바뀌는 내용·다시 반영될 점검·초기화될 카드를 미리 보여주고, 저장하면 영향받는 카드만 결정 대기로 돌아간다. 개업일만 바꾸면 체크리스트 날짜만 바뀐다 |
| S6 | 계정 전환 | 다른 계정으로 로그인하면 가게·결과·체크리스트가 섞이지 않는다. 예시 계정은 가입 없이 열린다 |
