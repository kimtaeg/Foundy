# 요식업 창업 규제 분석 AI 에이전트 구현 설계

## 1. 프로젝트 개요

요식업 창업자가 업종, 주소, 매장 면적, 층수, 메뉴, 직원 수 등의 정보를
입력하면 법령 및 공공데이터를 수집하고, 적용 조건을 검증한 뒤 창업자에게
필요한 인허가·법적 의무·준비 서류·일정을 안내하는 AI 에이전트를
구현한다.

핵심은 단순히 법령을 검색해 보여주는 것이 아니라, **창업자의 사업 조건에
따라 실제로 확인해야 할 의무사항을 선별하고 실행 가능한 체크리스트로
변환하는 것**이다.

### 핵심 원칙

-   법령 API: 법령의 공식 원문과 개정 정보를 수집한다.
-   공공데이터 API: 사업장 주소·건축물·인허가 등 실제 조건을 확인한다.
-   RAG: 창업 조건과 관련된 법령 조문을 검색한다.
-   규칙 엔진: 법령의 적용 요건을 명시적인 조건으로 검증한다.
-   AI API: 검증 결과를 이해하기 쉬운 설명과 작업 목록으로 변환한다.
-   데이터베이스: 법령 원문, 적용 규칙, 창업자 정보, 의무사항 및 일정을
    관리한다.

> AI가 법적 결론을 임의로 만들어내지 않도록 한다. 법령 원문과 적용
> 조건을 근거로 판정하고, 정보가 부족하거나 예외 여부를 확인할 수 없으면
> `확인 필요`로 분류한다.

## 2. 전체 처리 아키텍처

``` text
[창업자]
  |
  | 업종, 주소, 면적, 층수, 메뉴, 직원 수 등 입력
  v
[Frontend]
  |
  v
[Backend API]
  |
  v
[창업 정보 구조화]
  |  자연어 입력을 표준 JSON으로 변환
  v
[Analysis Service]
  |
  +---------------------------+
  |                           |
  v                           v
[법령 데이터 수집/조회]       [공공데이터 수집/조회]
  |                           |
  | 법률·시행령·시행규칙       | 건축물·인허가·지역 정보
  |                           |
  +-------------+-------------+
                |
                v
       [RAG 검색 + 규칙 엔진]
                |
                | 관련 조문 검색 및 적용 조건 검증
                v
            [AI Service]
                |
                | 근거 기반 설명 및 결과 구조화
                v
       [맞춤형 규제 분석 결과]
                |
                v
 [체크리스트 / 준비 일정 / 변경 알림]
                |
                v
          [PostgreSQL]
```

### 구성 요소별 역할

  구성 요소        역할
  ---------------- -----------------------------------------
  Frontend         창업자 정보 입력 및 분석 결과 표시
  Backend API      인증, 요청 처리, 분석 작업 관리
  Law Collector    법령 API 호출 및 법령 데이터 수집
  Data Collector   공공데이터 API 호출 및 사업장 정보 수집
  RAG Retriever    관련 법령 조문 검색
  Rule Engine      법령 적용 요건 및 예외 조건 검증
  AI Service       분석 결과 설명, 요약, 체크리스트 생성
  PostgreSQL       사용자, 법령, 규칙, 의무사항, 일정 저장
  pgvector         법령 조문 임베딩 및 유사도 검색

## 3. 활용할 외부 API

외부 API는 크게 법령 API, 공공데이터 API, AI API 세 종류로 구분한다.

### 3.1 법령 API

**국가법령정보센터 법령정보 공동활용 API**

공식 사이트: - https://www.law.go.kr/ - https://open.law.go.kr/

활용 목적: - 현행 법령 목록 검색 - 법령 본문 및 조문 조회 - 법령 시행일
확인 - 법령 개정 이력 확인 - 시행령·시행규칙 및 행정규칙 확인 - 관련
법령 탐색

요식업 관련 초기 수집 대상 예시:

  -----------------------------------------------------------------------
  법령                                주요 확인 내용
  ----------------------------------- -----------------------------------
  식품위생법                          영업신고, 위생교육, 건강진단, 시설
                                      및 위생 기준

  식품위생법 시행령·시행규칙          영업 유형, 시설 기준, 신고 절차 등
                                      세부 요건

  농수산물의 원산지 표시 등에 관한    음식점 원산지 표시 의무
  법률                                

  식품 등의 표시·광고에 관한 법률     식품 표시 및 광고 관련 의무

  축산물 위생관리법                   축산물 취급·유통 관련 기준

  근로기준법                          근로계약, 임금, 근로시간, 휴게시간
                                      등

  최저임금법                          최저임금 준수

  건축법                              건축물 용도 및 영업 가능 여부 관련
                                      사항

  국토의 계획 및 이용에 관한 법률     용도지역별 행위 제한

  폐기물관리법                        음식물류 폐기물 등 처리

  하수도법                            오수 및 배수 관련 기준

  다중이용업소의 안전관리에 관한      해당 업종·시설의 안전시설 및 소방
  특별법                              관련 의무
  -----------------------------------------------------------------------

위 목록은 초기 조사 대상이다. 실제 적용 여부는 업종, 사업장 구조, 면적,
취급 품목, 직원 고용 형태 및 지역 등에 따라 달라진다.

#### 법령 API 호출 흐름

1.  법령 검색 API로 `식품위생법` 검색
2.  검색 결과에서 법령 ID 등 식별 정보 확보
3.  법령 본문 API로 상세 조문 조회
4.  법령명, 법령 ID, 조문 번호, 조문 내용, 시행일, 개정 정보 저장
5.  시행령·시행규칙 및 관련 행정규칙도 연결해 수집

요청 형식 예시(실제 파라미터와 응답 형식은 공식 API 가이드에서 확인):

``` http
GET https://www.law.go.kr/DRF/lawSearch.do
    ?OC={발급받은인증키}
    &target=law
    &type=JSON
    &query=식품위생법
```

법령 본문 조회 예시:

``` http
GET https://www.law.go.kr/DRF/lawService.do
    ?OC={발급받은인증키}
    &target=eflaw
    &type=JSON
    &ID={법령ID}
```

API의 상세 요청 변수, 인증 방식, 응답 형식, 이용 조건은 최신 공식 개발
가이드를 기준으로 구현한다.

### 3.2 공공데이터 API

법령 원문만으로는 특정 사업장의 실제 조건을 확인할 수 없다. 주소와
건축물 정보 등을 공공데이터로 보완한다.

  필요한 데이터            활용 목적
  ------------------------ ------------------------------------
  일반음식점 인허가 정보   업소 인허가 현황 및 업종 정보 확인
  식품 관련 인허가 정보    식품 영업 관련 행정 데이터 확인
  건축물대장 정보          건축물 용도, 층수, 면적 등 확인
  토지이용계획 정보        용도지역 등 입지 관련 조건 확인
  식품안전 정보            식품 위생 관련 공개 정보 확인

참고 사이트: - 공공데이터포털: https://www.data.go.kr/ - 식품안전나라:
https://www.foodsafetykorea.go.kr/ - 정부24: https://www.gov.kr/

주의사항: - 건축물 용도나 면적만으로 음식점 영업 가능 여부를 단정하지
않는다. - 용도지역, 건축물의 세부 용도, 시설 기준, 조례 및 개별 제한을
함께 확인한다. - API 데이터가 최신인지, 조회 기준일이 언제인지
기록한다. - 공공데이터 조회 결과는 법적 판단 그 자체가 아니라 판단을
위한 근거 자료로 취급한다.

### 3.3 AI API

Gemini API 또는 OpenAI API 등을 활용할 수 있다.

AI API의 역할: - 자연어 창업 정보 구조화 - 관련 법령 검색어 생성 -
검색된 법령 조문 요약 및 비교 - 규칙 엔진 결과를 자연어로 설명 - 준비
서류와 실행 단계 정리 - 사용자 질문에 근거 기반 답변 제공

AI는 법령 원문을 대체하지 않는다. AI가 생성한 설명과 공식 법령 원문을
분리해 저장하고, 결과에 법령명·조항·시행일·공식 출처를 표시한다.

## 4. 창업자 정보 구조화

사용자가 자연어로 입력한 내용을 분석에 활용할 수 있는 표준 데이터로
변환한다.

### 입력 예시

> 시흥시에서 80㎡ 규모의 삼겹살집을 열려고 해. 직원은 3명이고 2층에
> 입점할 예정이야.

### 구조화 결과 예시

``` json
{
  "business_type": "일반음식점",
  "address": "경기도 시흥시",
  "area_sqm": 80,
  "floor": 2,
  "menu": ["삼겹살"],
  "employee_count": 3,
  "alcohol_sales": null
}
```

중요한 설계 원칙: - 사용자가 입력하지 않은 값은 임의로 추정하지 않고
`null`로 둔다. - AI가 추출한 값과 공공데이터로 검증한 값을 구분한다. -
주소, 면적, 층수 등 핵심 정보에는 출처와 확인 상태를 기록한다. - 분석에
필수적인 정보가 없으면 사용자에게 추가 입력을 요청한다. - 업종은
사용자가 선택한 업종과 실제 영업 형태가 일치하는지 별도로 확인한다.

### 권장 필드

  필드                  설명
  --------------------- -----------------------------------
  business_type         일반음식점, 휴게음식점, 제과점 등
  address               사업장 주소
  area_sqm              영업장 면적
  floor                 층수
  menu                  판매 메뉴 및 취급 품목
  employee_count        직원 수
  alcohol_sales         주류 판매 여부
  delivery              배달 영업 여부
  outdoor_seating       외부 테라스·옥외영업 여부
  building_use          건축물대장상 용도
  business_start_date   영업 예정일

## 5. RAG와 규칙 엔진 결합

이 프로젝트에는 RAG와 규칙 엔진을 함께 사용하는 방식을 권장한다.

  기술        담당 역할
  ----------- -------------------------------------------
  RAG         창업 조건과 관련된 법령 조문 검색
  규칙 엔진   조문에 명시된 적용 요건 및 예외 조건 검증
  AI API      검증 결과를 요약하고 사용자에게 설명

### 5.1 법령 데이터 수집 및 분할

법령 원문을 문서 전체 단위로만 저장하지 않고 조문 단위로 분할한다.

예를 들어 다음 정보를 하나의 조문 레코드로 관리한다.

``` json
{
  "law_name": "식품위생법",
  "article_number": "제36조",
  "paragraph": null,
  "content": "실제 법령 API에서 가져온 조문 내용",
  "effective_date": "실제 시행일",
  "source_url": "공식 법령 원문 URL"
}
```

조문 단위로 관리하면 특정 의무사항과 직접 관련된 근거를 검색하고
제시하기 쉽다.

### 5.2 임베딩 및 검색

1.  조문 텍스트를 임베딩 모델에 전달한다.
2.  생성된 벡터를 PostgreSQL의 pgvector에 저장한다.
3.  창업자 조건을 검색 문장 또는 검색 벡터로 변환한다.
4.  관련 조문을 유사도 기반으로 검색한다.
5.  법령명, 조항, 시행일, 원문 및 출처를 AI에 전달한다.

단, 벡터 유사도만으로 법령을 선정하지 않는다. 법령명, 업종, 조문 분류,
시행 상태 등의 메타데이터 필터와 키워드 검색을 함께 사용하는 것이 좋다.

### 5.3 규칙 엔진

법령의 적용 요건을 명시적인 조건으로 관리한다.

가상 규칙 예시:

``` json
{
  "rule_id": "EXAMPLE-001",
  "law_name": "관련 법령",
  "conditions": {
    "business_type": ["일반음식점"],
    "area_sqm": {
      "min": 100
    }
  },
  "required_action": "관련 시설 기준 확인",
  "source_article": "관련 조항"
}
```

위 예시는 규칙 엔진의 데이터 형태를 설명하기 위한 가상 데이터이며, 실제
법적 기준이 아니다. 실제 규칙은 현행 법령의 적용 요건과 예외를 확인한 뒤
작성한다.

#### 판정 결과

  상태        의미
  ----------- ---------------------------------------------------
  적용        필요한 조건이 충족되고 적용 근거가 확인됨
  미적용      적용 요건에 해당하지 않는다는 점이 확인됨
  확인 필요   추가 정보, 예외 검토 또는 관할 기관 확인이 필요함

규칙에는 다음 정보도 함께 저장하는 것이 좋다. - 적용 조건 - 제외 조건 및
예외 - 필요한 추가 입력 - 근거 법령 및 조항 - 시행일 및 적용 기간 - 규칙
작성·검토 이력 - 최종 검토 담당자 또는 검토 상태

## 6. AI API에 전달할 데이터와 프롬프트

법령 검색 결과와 규칙 엔진의 판정 결과를 함께 AI에 전달한다.

### 전달 데이터 예시

``` json
{
  "founder": {
    "business_type": "일반음식점",
    "address": "경기도 시흥시",
    "area_sqm": 80,
    "floor": 2,
    "employee_count": 3
  },
  "legal_documents": [
    {
      "law_name": "식품위생법",
      "article": "제36조",
      "content": "실제 API에서 가져온 조문 내용",
      "effective_date": "실제 시행일",
      "source_url": "법령 원문 URL"
    }
  ],
  "rule_results": [
    {
      "category": "영업신고",
      "status": "확인 필요",
      "reason": "영업시설 기준 및 신고 요건 추가 확인 필요"
    }
  ]
}
```

### 시스템 프롬프트 예시

``` text
너는 대한민국 창업 관련 법령을 분석하는 AI 에이전트다.

주어진 창업자 정보, 공식 법령 데이터, 규칙 엔진 결과를 기반으로
창업자에게 필요한 의무사항을 설명하라.

다음 원칙을 반드시 지켜라.

1. 제공된 법령 데이터에 근거하여 답변한다.
2. 법령에 없는 내용을 임의로 만들어내지 않는다.
3. 적용 여부가 불분명하면 확인 필요로 분류한다.
4. 법령명과 조항 번호를 표시한다.
5. 법령의 시행일과 적용 시점을 확인한다.
6. 필요한 준비 서류와 절차를 설명한다.
7. 규칙 엔진의 판정과 다른 결론을 임의로 만들지 않는다.
8. 근거 자료가 부족하면 추가 확인이 필요하다고 안내한다.
9. 공식 출처 링크를 함께 제공한다.

출력 항목:
- 의무사항
- 적용 여부
- 적용 근거
- 준비해야 할 사항
- 미이행 시 발생할 수 있는 위험
- 공식 출처
- 추가 확인이 필요한 정보
```

### AI 응답 예시 구조

``` json
{
  "obligations": [
    {
      "title": "영업신고 관련 확인",
      "status": "확인 필요",
      "reason": "영업 유형과 시설 기준에 대한 추가 확인이 필요합니다.",

      "article": "관련 조항",
      "required_actions": [
```

## 7. 데이터베이스 설계

PostgreSQL을 기본 데이터베이스로 사용하고, pgvector를 통해 법령 조문
벡터 검색을 구현한다.

  테이블                  주요 저장 데이터
  ----------------------- --------------------------------------
  `users`                 사용자 정보
  `founder_profiles`      창업자 및 사업장 정보
  `laws`                  법령명, 법령 ID, 시행일, 개정 정보
  `law_articles`          조문 번호, 조문 내용, 법령 연결 정보
  `law_embeddings`        조문별 임베딩 벡터
  `applicability_rules`   법령 적용 조건 및 예외
  `legal_obligations`     창업자별 분석된 의무사항
  `compliance_tasks`      준비 일정, 완료 여부, 마감일
  `law_change_logs`       법령 변경 내역 및 변경 감지 기록

### 데이터 관리 시 유의사항

-   법령 원문과 AI가 생성한 설명을 분리한다.
-   법령의 시행일과 수집 시점을 기록한다.
-   개정 전후 조문을 구분할 수 있도록 버전 관리한다.
-   각 의무사항이 어떤 법령·조문·규칙에서 도출되었는지 추적 가능하게
    한다.
-   창업자 정보가 변경되면 기존 분석 결과를 다시 평가한다.
-   법령 변경 시 영향받는 규칙과 사용자 데이터를 추적할 수 있도록 연결
    관계를 설계한다.

## 8. 법령 최신성 및 변경 감지

법령은 계속 개정되므로 API를 통해 데이터를 최초 한 번 수집하는 것으로
끝내면 안 된다.

권장 처리 흐름:

``` text
[정기 실행 작업]
      |
      v
[법령 API에서 최신 정보 조회]
      |
      v
[기존 DB의 법령 정보와 비교]
      |
      +---- 변경 없음 ----> 종료
      |
      v
[개정 법령 및 조문 저장]
      |
      v
[변경된 조문과 연결된 규칙 탐색]
      |
      v
[영향받는 창업자 및 사업장 탐색]
      |
      v
[기존 의무사항 재검토]
      |
      v
[변경 사항 및 확인 필요 항목 알림]
```

법령이 개정되었다고 해서 모든 사업자에게 동일한 영향이 발생하는 것은
아니다. 개정 조문의 시행일, 적용례, 경과조치, 대상 업종 등을 검토한 후
영향받는 사용자만 선별해야 한다.

## 9. 실제 사용자 시나리오

### 입력 정보

  항목        입력값
  ----------- ------------------
  업종        일반음식점
  주소        경기도 시흥시
  메뉴        삼겹살, 김치찌개
  매장 면적   80㎡
  층수        지상 2층
  직원 수     3명

### AI 에이전트가 수행할 작업

1.  사용자 입력을 표준 데이터로 구조화한다.
2.  주소를 기반으로 사업장 관련 공공데이터를 조회한다.
3.  건축물 용도, 면적, 층수 등 확인 가능한 정보를 검증한다.
4.  식품위생법, 원산지표시법, 근로기준법 등 관련 법령을 검색한다.
5.  소방·건축 관련 법령 및 지역별 자치법규를 확인한다.
6.  RAG로 관련 조문을 검색한다.
7.  규칙 엔진으로 적용 여부를 판정한다.
8.  AI가 근거와 함께 의무사항 및 준비 절차를 설명한다.
9.  창업자별 체크리스트와 일정을 생성한다.

### 결과 화면 예시

  분야     확인 항목                           상태
  -------- ----------------------------------- -----------
  입지     건축물 용도 및 영업 가능 여부       확인 필요
  인허가   일반음식점 영업신고                 준비 필요
  위생     위생교육 및 건강진단 등             확인 필요
  원산지   육류·쌀·김치 등 표시 대상 확인      준비 필요
  소방     업종 및 건물 구조에 따른 안전시설   확인 필요
  고용     근로계약 및 임금 관련 의무          준비 필요

위 표는 서비스 화면 예시이며, 실제 사업장에 대한 법적 판정 결과가
아니다.

## 11. 단계별 MVP 개발 로드맵

### 1단계: 법령 데이터 수집

-   국가법령정보센터 API 연동
-   식품위생법 및 시행령·시행규칙 수집
-   원산지표시법 수집
-   근로기준법 및 최저임금법 수집
-   법령과 조문을 PostgreSQL에 저장

**완료 기준:** 법령명과 조문 번호를 이용해 DB에서 원문을 조회할 수 있다.

### 2단계: 창업자 정보 분석

-   일반음식점 업종 선택
-   주소, 면적, 층수 입력
-   메뉴 및 직원 수 입력
-   AI를 이용한 자연어 정보 구조화
-   누락 정보 확인 및 추가 질문

**완료 기준:** 창업자 정보를 일관된 JSON 구조로 변환할 수 있다.

### 3단계: RAG 및 규칙 엔진

-   조문 단위 분할
-   임베딩 생성 및 pgvector 저장
-   관련 조문 검색
-   주요 적용 조건과 예외 규칙 작성
-   적용·미적용·확인 필요 판정

**완료 기준:** 입력 조건에 따라 관련 법령 조문과 규칙 판정 결과를 반환할
수 있다.

### 4단계: AI 분석 결과 생성

-   검색된 법령과 규칙 결과를 AI에 전달
-   법령별 의무사항 추출
-   준비 서류 및 절차 안내
-   공식 출처 연결
-   응답 스키마 검증

**완료 기준:** 근거 조문이 연결된 창업자 맞춤형 분석 결과를 생성할 수
있다.

### 5단계: 일정 관리 및 변경 감지

-   미완료 의무사항 체크리스트
-   준비 기한 및 진행 상태 관리
-   정기적인 법령 변경 감지
-   개정 조항과 관련 규칙 연결
-   영향을 받는 창업자에게 변경 사항 알림

**완료 기준:** 일회성 법령 검색을 넘어 지속적인 창업 규제 관리가
가능하다.

## 12. 핵심 차별점과 구현 시 주의사항

### 핵심 차별점

기존 법령 검색 서비스는 사용자가 직접 법령을 검색하고 해석해야 한다. 이
서비스는 창업자의 상황을 먼저 파악하고 필요한 법령과 의무사항을
선별한다.

-   창업자가 어떤 정보를 입력했는지 파악한다.
-   사업 조건에 따라 필요한 법령을 선별한다.
-   법령의 적용 요건과 예외를 검증한다.
-   해야 할 일을 구체적인 체크리스트로 안내한다.
-   법령이 개정되면 기존 사업자의 의무사항에 미치는 영향을 다시
    검토한다.

### 반드시 고려할 사항

1.  **법적 정확성:** AI의 자연어 판단만으로 법적 적용 여부를 확정하지
    않는다.
2.  **근거 추적:** 모든 의무사항에 법령명, 조항, 시행일, 원문 출처를
    연결한다.
3.  **최신성:** 법령 개정일과 시행일을 구분하고 적용 시점을 검증한다.
4.  **예외 및 경과조치:** 개정 법령의 적용례와 경과조치를 확인한다.
5.  **정보 부족:** 필요한 정보가 없으면 `확인 필요`로 표시한다.
6.  **지역별 규정:** 지자체 조례와 개별 사업장 조건을 함께 검토한다.
7.  **행정기관 확인:** 해석이 불명확하거나 현장 확인이 필요한 사안은
    관할 기관 확인을 안내한다.
8.  **데이터 출처:** 공식 원문과 AI가 생성한 설명을 명확히 구분한다.

## 13. 최종 구현 방향

초기에는 **일반음식점 하나를 대상으로 작동하는 프로토타입**을 만드는
것을 권장한다.

첫 번째 목표는 다음 흐름을 실제로 연결하는 것이다.

``` text
창업자 정보 입력
    ↓
AI를 통한 정보 구조화
    ↓
법령 API를 통한 법령 수집
    ↓
PostgreSQL에 법령 및 조문 저장
    ↓
관련 조문 검색
    ↓
규칙 엔진을 통한 적용 조건 검증
    ↓
AI를 통한 분석 결과 생성
    ↓
근거가 연결된 체크리스트 제공
```

이 흐름이 완성되면 공공데이터 연동, 다른 음식점 업종 지원, 법령 변경
감지 및 일정 관리 기능을 순차적으로 확장한다.

**서비스의 핵심은 법령 API와 AI API를 단순히 연결하는 것이 아니라, 공식
법령 데이터를 창업자의 실제 조건과 연결해 실행 가능한 의무사항으로
바꾸는 데 있다.**
