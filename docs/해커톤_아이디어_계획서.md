## 1. 한눈에 보기

**가게 주소·업종·개업일만 넣으면, 창업에 필요한 점검·개업 체크리스트·서류 안내·지원사업 정보가 공공 데이터를 바탕으로 자동으로 채워지고, 개업 후에도 바뀐 것을 먼저 알려주는 서비스.**

- 대상: **어디에서 사업을 할지 이미 정한** 청년 창업가 (시연은 카페·음식점). 입지를 아직 정하지 못한 사람을 위한 입지 추천은 판단 위험이 커서 만들지 않는다
- 시작: 로그인 후 가게를 한 번 등록하면 내 계정에 저장되고, 이후에는 언제든 이어서 쓴다
- 풀려는 문제: **"창업가는 자기가 뭘 모르는지 모른다."** 뭘 확인해야 하는지 몰라서 묻지도 못하고, 계약과 인테리어를 마친 뒤에야 문제를 알게 된다
- 방식: AI에 **공공데이터 조회**를 연결해, 내 가게의 사실을 확인하고 자동으로 채워지는 대시보드

### 문제의 근거: 청년 창업은 더 빨리, 더 많이 문을 닫는다

- 위 조사는 **소상공인 전체**(전 연령) 대상이고 청년만 따로 본 값이 아니다. 청년 대상 값은 앞의 폐업률 표만 있다
- **찾지 못한 근거**: 입지 선택이 어려웠다는 예비 창업자 설문, 상권·경쟁 정보를 구하기 어렵다는 설문, 세금 신고가 부담이라는 설문, 폐업 이유 중 입지·상권 비중. 개별 신고·세무 알림과 입지 판단의 필요성은 현재 자료만으로 직접 입증되지 않으며, 소상공인시장진흥공단 창업 실태조사 원자료에서 확인이 필요하다
- 정책 인지 조사의 76.2%는 **디지털·AI 지원사업**에 한정된 값이다. 지원사업 전반의 인지율로 쓰면 안 된다

- 청년은 중소기업창업지원법의 청년창업 기준에 맞춰 **39세 이하**로 본다. 폐업률은 39세 이하를 한 묶음으로 낸 값이 없어 30세 미만과 30대를 나란히 적었고(두 구간 모두 전체 평균보다 높다), 40대 수치는 확인하지 못했다
- 5년 생존율은 39세 이하 기업이 40세 이상보다 낮지만 격차가 줄고 있다(2011년 5.6%p → 2018년 5.1%p, 둘 다 상승 추세). "생존율이 낮다"는 근거로는 약하므로 소개서에서는 폐업률을 앞세운다
- 폐업 통계는 청년 창업이 더 많이 실패한다는 사실을, 위 자료는 창업자가 정보와 절차에서 막힌다는 사실을 보여준다. 다만 "청년이 인허가를 몰라서 폐업한다"를 직접 증명하는 자료는 없으므로 그렇게 단정해 쓰지 않는다
- 장애요인 조사와 민원 분석은 청년만 따로 본 자료가 아니다 (민원은 30대 35.1%, 40대 28.8%)
- 소개서에 인용하기 전에 보도 기사가 아닌 원자료(국세통계포털, 기업생멸행정통계)에서 수치를 다시 확인한다

### 동작 방식: 데이터 수집 → AI 판정 → 알림

| 단계 | 하는 일 | 누가 하나 |
|---|---|---|
| 1. 입력 1회 | 로그인 후 첫 설정에서 주소, 업종, 상호, 개업 예정일을 넣는다. 판단에 필요한데 빠진 것만 되묻는다 (술 판매, 테라스, 직원 수, 자금) | 사용자 + AI(되묻기) |
| 2. 자동 수집 | 건축물대장, 상표, 법령, 지원사업 공고를 한꺼번에 조회한다 (주변 상권 조회는 마지막에 구현) | 데이터 조회 |
| 3. AI 판정 | 내 가게에 어떤 신고·인허가가 해당하는지, 지원사업 자격에 맞는지, 무엇이 위험한지를 조회 결과를 근거로 판정한다. 날짜·금액 계산과 나이·업력 같은 숫자 조건 대조는 계산 도구를 불러서 한다 | AI (+ 계산 도구) |
| 4. 해석·요약 | 여러 조회 결과를 엮어 해석하고, 공고문·조문을 쉬운 말로 요약·분류한다. 근거를 못 찾으면 판단을 보류한다 | AI |
| 4-1. 해결안 만들기 | 문제가 나온 항목마다 선택지와 추천, 문의할 기관 전화번호를 붙인다. 금액·날짜 차이는 계산 도구가 계산한다 | AI (+ 계산 도구) |
| 5. 주기 실행 | 저장된 가게마다 2~4단계를 다시 돌려 달라진 점만 알림으로 보낸다 | 자동 실행 |

판정은 AI가 한다. 공고문의 자격 조건이나 법 조문은 글로 쓰여 있고 가게마다 사정이 달라서, 미리 정해 둔 규칙으로는 다 담을 수 없기 때문이다. 대신 AI는 반드시 조회한 데이터를 근거로 판정하고, 날짜 계산처럼 답이 하나로 정해진 일은 계산 도구에 맡긴다.

## 2. 사용자 예시: 이서연 씨의 카페 창업

> 아래 인물과 수치는 설명을 위한 가상 설정이다.

**이서연(29세)** — 마케팅 회사에서 4년 일하고 퇴사했다. 모은 돈 4천만 원으로 서울 성수동에 작은 카페를 열 계획이다. 바리스타 자격증은 있지만 장사는 처음이고, 자금이 빠듯해 지원사업이 꼭 필요하다. 행정 절차는 뭐부터 해야 할지 모른다.

| 장면 | 이서연 씨의 상황 | 서비스가 하는 일 | 메뉴 |
|---|---|---|---|
| 1 | 자리는 성수동 1층 상가로 정했다. 로그인 후 주소, 업종(카페), 상호('모노커피'), 개업일(내년 3월)만 입력한다 | 계정에 가게를 저장하고, 빠진 것만 되묻고(술 판매, 테라스, 직원, 자금), 곧바로 데이터를 조회해 아래 메뉴를 전부 채운다 | 로그인·첫 설정 |
| 2 | (마지막에 구현) 계약 직전이다. 주변에 카페가 얼마나 있고 어떤 가게인지, 내 가격이 비싼 건지 모른다 | 지도에 주변 카페·음식점을 자동으로 띄우고 경쟁 강도, 프랜차이즈 비율, 가격대 위치, 이 자리에서 눈여겨볼 점을 정리한다 | 상권 분석 |
| 3 | 건물 용도가 맞는지, 위반건축물은 아닌지, 이름이 겹치는 상표는 없는지 모른다 | 건축물대장·법령·상표를 조회해 문제가 있으면 "술을 팔 수 없는 자리예요 → 술 빼고 시작 / 용도변경 / 다른 자리 알아보기" 선택지와 추천, 구청 건축과 전화번호와 할 일 1개를 붙여 준다. 이서연 씨는 `[추천대로 진행]`만 누른다 | 점검 리포트 |
| 4 | 구청에 전화하려는데 뭐라고 말해야 할지 모른다 | AI 상담에 물으면 번호, 30초 통화 순서, 꼭 물어볼 질문을 준비해 주고, 통화 뒤 결과를 카드에 기록한다. 완료하면 **다음으로 할 일**을 자동으로 정리하고 체크리스트의 같은 항목도 자동으로 체크한다 | 점검 리포트, AI 상담 |
| 5 | 뭘 언제 신고해야 하는지 모른다 | 3월 개업일에서 거꾸로 계산한 개업 체크리스트를 시기별·카테고리별·**달력**으로 보여 주고, 서류·기관·기한을 정리하고, 서류가 필요한 항목은 어디서 받는지(공식 사이트 링크와 찾는 방법)를 알려 준다 | 개업 체크리스트, 서류함 |
| 6 | 청년 창업 지원사업이 있는지조차 모른다 | 나이·지역·업종에 맞는 지원사업을 **포스터 카드**로 보여 주고, 신청 가능성과 조건별 근거를 표시하며 마감일을 체크리스트에 넣는다 | 지원사업, 알림 센터 |
| 7 | 개업일을 4월로 미루고 싶다 | 마이페이지에서 바꾸면 바뀐 내용과 영향받는 점검을 미리 보여 주고, 개업일은 체크리스트 날짜만 다시 계산한다. AI 상담에 말해도 변경을 제안하고 확인하면 반영한다 | 마이페이지, AI 상담 |
| 8 | 개업 6개월 후, 장사에 바빠 행정을 챙길 틈이 없다 | "부가세 신고 확인", "반경 300m 신규 카페 개업", "식품 표시 규정 개정" 같은 알림을 먼저 보내고, 알림마다 바로 처리할 곳을 붙인다 | 알림 센터 |

## 3. 메뉴 구성

| 메뉴 | 한 줄 설명 | 주로 쓰는 시기 |
|---|---|---|
| **내 가게 홈** | 결정할 것, 내가 직접 할 일, 다음으로 할 일, 새 알림을 모아 보는 첫 화면 | 항상 |

| **지원사업** | 내 조건에 맞는 청년 창업 지원사업을 포스터 카드로 보고 자격을 판정 | 항상 |
| **알림 센터** | 결정 필요, 다음 할 일, 마감 임박, 변경 감지, 새 지원사업을 모아 보고 바로 처리 | 항상 |

화면은 대시보드가 중심이고, 대화창은 보조다. 대화는 입력을 보완할 때(되묻기)와 "이 항목은 왜 이런가요?"처럼 결과를 물어볼 때 쓴다. 내 가게 홈에는 **결정할 것**(선택지가 있는 항목)과 **내가 직접 할 일**(사용자가 직접 해야 하는 일 1개씩, 소요 시간과 함께)을 먼저 보여준다. 로그인 전에는 로그인 화면만 보이고, 가게가 없는 계정은 첫 설정으로 보낸다.

## 4. 기능 상세

### 4-1. 로그인과 첫 설정

- **로그인**: 아이디·비밀번호로 회원가입·로그인한다. 계정마다 가게·점검 결과·체크리스트·알림·상담 기록이 따로 저장된다. 가입 없이 둘러볼 수 있는 **예시 계정**(이서연)이 있다
- **첫 설정**: 로그인했는데 가게가 없으면 가게 정보를 한 번 입력한다. 계정당 가게는 하나다
  - **입력**: 주소·층, 업종, 상호, 개업 예정일, 출생 연도(선택, 지원사업 조건에만 사용). 메뉴·광고 문구는 점검을 붙일 때(마지막에 구현) 입력란을 추가한다
  - **AI가 하는 일**: 판단에 필요한데 빠진 정보만 골라 질문한다
  - **예시**: "술도 판매하시나요?", "테라스나 가게 앞 공간을 쓰시나요?", "직원을 고용하시나요?", "준비된 자금은 얼마인가요?"
  - **왜 필요한가**: 술을 팔면 신고 업종이 달라지고, 직원이 있으면 4대보험 일정이 생긴다. 사용자는 이 정보가 중요한지 모르기 때문에 서비스가 먼저 물어야 한다
- **대상은 입지를 정한 사람**: 주소를 입력하는 것이 시작이다. 입지를 정하는 것을 돕는 기능(지역별 후보 상권 추천, 후보 자리 비교, 매물 비교)은 판단 위험이 커서 만들지 않는다
- **예시로 해보기**: 입력 없이 이서연 씨 사례로 끝까지 볼 수 있다 (저장된 결과라 외부 API가 실패해도 동작한다)

### 4-2. 점검 리포트

| 점검 | 자동으로 가져오는 데이터 | 결과 예시 |
|---|---|---|
| 건물 | 건축물대장 (용도, 위반건축물 여부) | "이 자리에서는 술을 팔 수 없어요. 1층이 카페(휴게음식점)까지만 가능한 용도예요." |
| 법·인허가 | 국가법령정보 (업종 규칙에 연결된 조문) | "맥주를 팔 계획이면 휴게음식점이 아니라 일반음식점으로 신고해야 해요." |
| 상호 | KIPRIS 상표 정보 | "'모노커피'와 비슷한 상표가 이미 등록돼 있어요. 겹치지 않는 이름: ○○, △△" |

- 결과는 **계약 전 꼭 확인 / 개업 전 할 일 / 운영 중 주의** 세 묶음으로 보여준다
- 모든 항목에 근거(조문 원문·링크, 조회 결과)를 함께 적되, 근거는 "자세히 보기"로 접어 둔다
- 항목마다 **위반 소지 높음 / 낮음 / 판단 불가**를 표시한다 (문제없음 항목은 접어서 표시)

**결과 카드: 판단을 던지지 않고 결과물과 결정 한 번을 준다**

문제를 알려주고 "구청에 확인하세요"로 끝내면 사용자가 다시 판단해야 하고, 법 구조를 이해해야 결론에 닿는다. 그래서 문제가 있는 항목은 아래 구조로 보여준다. 에이전트가 조사·비교·작성까지 끝내서, 사용자 몫을 **결정, 서명, 방문**으로 줄인다.

| 칸 | 내용 |
| --- | --- |
| 결론 | 한 줄, 결과 중심의 쉬운 말 ("이 자리에서는 술을 팔 수 없어요") |
| 안 하면 생기는 일 | 돈·시간 기준 ("이대로 계약하면 영업신고가 반려돼 보증금이 묶일 수 있어요") |
| 선택지 | 에이전트가 비교해서 정리 (예: ① 술 빼고 카페로 시작 ② 용도변경 신청 ③ 다른 자리를 알아보기). 금액·기간은 근거가 있을 때만 계산 도구가 계산한다 |
| 추천 | 기본 선택 하나와 이유 |
| 연락처·통화 준비 | **문의할 기관 전화번호**(복사 가능). 통화할 때 물어볼 질문은 AI 상담의 통화 준비 도우미가 정리해 준다. 문의 문구·특약·서류 초안은 만들지 않는다 |
| 당신이 할 일 | 1개와 소요 시간 ("구청 건축과에 전화로 문의하기 (3분)"), `[추천대로 진행]` 버튼 한 번으로 가게 정보·체크리스트가 자동으로 바뀐다 |

- 선택지의 기간·금액은 **근거가 있을 때만** 숫자로 쓰고, 없으면 "확인 필요"로 표시한다. AI가 추정해서 채우지 않는다
- 선택지의 종류는 업종 규칙 묶음에 정해 둔 범위 안에서만 만든다
- 정부24 제출, 서명, 구청 방문, 전화는 자동화하지 않는다. 서비스는 그 직전까지를 대신한다. 웹 서비스라 문자 앱을 열 수 없어서 "문자 앱 열기"는 없고, 문의할 기관의 **전화번호를 보여 주고 복사**하게 한다. 전화번호는 AI가 만들지 않고 규칙 묶음·기관 데이터에서만 가져오며, 확인하지 못한 번호는 "예시 번호·걸기 전 확인"으로 표시한다

**결정 → 실행 → 완료: 선택한 뒤에도 끝까지 이어간다**

카드는 선택지를 고르면 끝나지 않고 3단계로 진행된다.

| 단계 | 화면 | 하는 일 |
| --- | --- | --- |
| 결정 | 선택지 비교, 추천 | 하나를 고르거나 `[추천대로 진행]`. 고르기 전에 "적용하면 이렇게 바뀌어요"를 미리 보여 준다 |
| 실행 | 적용한 방법, 바뀐 내용, 내가 할 일 | 가게 정보 before→after, 체크리스트 추가·변경, 판정 변화(위반 소지 높음 → 문제 없음)를 보여 주고, 기관 전화번호로 직접 문의한다. 문의했으면 "문의했어요"를 눌러 답변 대기로 둔다 |
| 완료 | 결과 메모, 다음으로 할 일 | 통화 결과를 메모하고 완료로 기록한다. 선택은 언제든 되돌릴 수 있다 |

- **다음으로 할 일(자동 정리)**: "문의했어요"나 "완료"를 누르는 순간 그 카드 안에 다음 할 일이 자동으로 생긴다. 이번 선택으로 **새로 생긴 할 일** → 아직 결정하지 않은 카드(위반 소지 높음 먼저) → 다른 카드의 직접 할 일 → 가장 가까운 체크리스트(기한·담당 기관 전화번호 포함) 순서로 최대 5개이고, 항목마다 바로 가는 버튼이 있다. "문의했어요" 단계에서는 "답변을 기다리는 동안 먼저 하세요"로 보여 준다. 정렬은 코드가 하고 AI는 쓰지 않는다. 같은 내용이 알림 센터에 "다음 할 일"로 남는다
- **체크리스트 자동 체크**: 점검 카드와 같은 일인 체크리스트 항목은 카드를 **완료**하면 자동으로 체크된다 (예: 영업신고 서류 카드 → 영업신고 서류 준비). 한 항목에 카드가 둘 이상 연결돼 있으면(건물 확인·임대차 계약 검토 ← 건물 용도 카드 + 위반건축물 카드) 모두 완료해야 체크된다. 카드를 되돌리면 자동 체크만 풀리고 직접 한 체크는 유지한다. 카드와 체크리스트 양쪽에 "연동됨" 표시가 나온다


### 4-3. 개업 체크리스트

일정표와 신고·인허가를 하나로 합쳤다. 개업 예정일에서 거꾸로 계산한 **시기**(계약 전 / 개업 4주 전 / 개업 직전 / 개업 후)와 **카테고리** 두 축으로 보고, 항목마다 완료 체크를 한다.

**개업일 기준 일정** — 개업 예정일에서 거꾸로 계산해 할 일의 순서와 기한을 만든다. 어떤 할 일이 필요한지는 AI가 판정하고, 날짜는 계산 도구로 계산한다.

> 프로토타입 일정 (개업일 기준): 계약 전 건축물대장 확인·임대차 계약 검토(D-56) → 상호·상표 확인(D-49) → 개업 4주 전 사업자등록(D-28)·영업신고 서류 준비(D-28)·식품위생교육(D-22) → 개업 직전 건강진단(D-10)·간판 기준 확인(D-6)·근로계약·고용(D-3, 직원이 있을 때) → 개업 후 표시 의무 점검(D+7). 선택지로 생기는 항목(다른 후보 자리·용도변경 문의·상표 최종 확인)은 계약 전에 끼어든다. 시기는 항목마다 정해 둔 값이고 날짜는 계산 도구가 개업일에서 계산한다 (실제 기간은 사전조사로 확정)

**카테고리별 정리** — 창업자가 알아야 할 신고·인허가를 묶어서 보여준다. 항목마다 필요 서류, 담당 기관, 기한, 근거를 표시한다. 서류가 필요한 항목은 서류를 어디서 받는지 알려 주고, 제출은 사용자가 직접 한다.

| 카테고리 | 들어가는 항목 예시 |
|---|---|
| 영업 인허가 | 영업신고, 위생교육, 건강진단 |
| 세무 | 사업자등록, 부가세·종합소득세 신고 일정 |
| 고용 | 근로계약서, 4대보험 (직원이 있을 때만 표시) |
| 건물·시설 | 건물 용도, 소방·안전 관련 확인 사항 |
| 간판·광고 | 간판 신고, 메뉴판·홍보 문구 주의 사항 |
| 표시 의무 | 원산지 표시, 가격 표시 |
| 정책 | 지원사업 신청 마감 (지원사업에서 자동 추가) |

사용자의 조건에 해당하지 않는 항목은 숨긴다. 직원이 없으면 고용 카테고리가 나오지 않는다.

**달력 보기** — 시기별·카테고리별 보기 옆에 **달력**을 둔다. 월 달력에 항목의 기한을 카테고리 색 점으로 찍고, 개업일은 깃발로 표시한다. 날짜를 누르면 옆 패널에 그날 할 일이 나오고 거기서 바로 체크할 수 있다. 지원사업 마감도 함께 보이고, 캘린더 파일(`.ics`)로 내보내 구글·애플 캘린더에 넣을 수 있다. 날짜는 모두 계산 도구가 정한 값이라 달력을 위한 별도 계산은 없다.

**필요 서류와 서류함** — 체크리스트 항목마다 필요한 서류를 **어디서 받는지** 안내한다. 서류를 대신 만들어 주지 않고, 서류별로 준비 여부를 체크하지도 않는다. 전체는 **서류함**에서 기한순으로 모아 본다 (서류 수, 완료한 항목의 서류 수, 남은 서류 수 요약).

| 항목 | 받는 곳 (공식 사이트 첫 화면) |
| --- | --- |
| 건축물대장 확인 | 정부24, 세움터(건축행정시스템) |
| 상호·상표 확인 | KIPRIS |
| 사업자등록 신청 | 홈택스 |
| 영업신고 | 정부24 (+ 관할 구청 위생과 전화번호) |
| 간판 설치 기준 | 정부24 옥외광고물 안내 (+ 관할 구청 전화번호) |
| 근로계약·4대보험 | 고용노동부 표준 근로계약서, 4대사회보험 정보연계센터 |
| 표시 의무 | 국립농산물품질관리원 원산지·가격 표시 안내 |

- 서류마다 서류 이름, 받는 곳, **찾는 방법**(어떤 메뉴를 누르면 되는지 한 줄)과 링크 버튼이 붙고, 링크는 새 탭으로 열린다
- **링크는 검증된 공식 사이트만** 쓴다. 첫 화면 주소만 쓰고 세부 신청 페이지 주소는 바뀌기 쉬워 쓰지 않는다. 링크는 배포 전에 사람이 확인한다
- **공식 서식은 대신 만들지 않는다.** 정부 서식은 해당 사이트에서만 효력이 있고, 발급·제출·서명은 사용자가 직접 한다
- 서류가 필요한 기관에 전화할 때는 번호를 함께 보여 주고, AI 상담에 "영업신고에 필요한 서류가 뭐예요?"라고 물으면 서류 목록과 받는 곳을 답한다
- 지원사업 상세에서도 K-Startup·기업마당 공식 사이트로 연결한다 (공고와 신청서는 공식 사이트에서 확인)

**점검 리포트와 연동** — 점검 카드와 같은 일인 항목에는 "점검 리포트와 연동" 표시가 붙고, 카드를 완료하면 자동으로 체크된다 (4-2).

### 4-4. 상권 분석 (마지막에 구현 · 현재 범위 제외)

> **구현은 맨 마지막으로 미룬다.** 핵심·시간되면 기능이 끝난 뒤 붙이고, 그 전까지는 다른 기능이 상권 분석에 의존하지 않는다. 프로토타입의 "상권 분석" 메뉴는 시연용 자리표시다. 아래는 붙일 때의 설계다.

- **대상**: 어디에서 사업을 할지 **이미 정한** 사용자. 정한 주소 주변을 분석하고, 주소를 바꾸면 마이페이지에서 저장한 뒤 다시 반영된다. 후보 자리를 직접 입력하거나 비교하지 않는다
- **자동으로 가져오는 데이터**: 카카오 로컬 카테고리 검색(카페 CE7, 음식점 FD6). 이름·거리·좌표·가게 링크가 오고 한 번에 최대 45건이며 총 개수는 별도로 받는다
- **화면 구성**
  - **지도**: 내 자리와 주변 경쟁 가게를 자동으로 표시한다. 카페/음식점 필터, 반경(100·200·300m) 전환, 가게를 누르면 이름·거리·카카오맵 링크가 나온다
  - **상권 요약**: 동종 업소 수, 지도에 표시된 수, 밀집도와 경쟁 수준, 업종 구성
  - **경쟁 강도**: 거리별 가게 수, 프랜차이즈와 개인 카페 비율, 디저트 계열 수, 가장 가까운 경쟁 가게 3곳. 프랜차이즈 구분은 가게 이름을 규칙으로 분류한 값이다
  - **가격 포지셔닝**: 내 아메리카노 가격을 넣으면 주변 가격 분포에서 저가·중간·고가 구간과 중앙값과의 차이를 보여 준다. 주변 메뉴·가격은 공개 데이터가 없어서 **예시 분포**이고 화면에 예시 배지가 붙는다
  - **이 자리에서 눈여겨볼 점**: 위 숫자에서 규칙으로 만든 참고 문구 (예: "프랜차이즈가 4곳(27%)이에요. 메뉴나 분위기로 차별화하는 편이 안전해요", "디저트 계열은 2곳뿐이에요")
  - **계약 전 현장에서 확인할 것**: 유동인구를 직접 세어 보기, 가까운 경쟁 가게의 영업 시간대·손님 수, 전 임차인이 영업을 접은 이유, 간판 시야와 동선
- **데이터가 없는 지표**: 폐업·개업 추이, 유동인구는 공개 데이터가 없어서 "데이터 없음"으로 두고 지어내지 않는다. 평균 임대료는 예시다
- **운영 중**: 새 경쟁 가게가 생기거나 주변 가격이 바뀌면 알림으로 알린다 (시점 이동 시연은 예시)

### 4-5. 지원사업

- **자동으로 가져오는 데이터**: K-Startup, 기업마당의 지원사업 공고
- **AI가 판정**: 공고문의 자격 조건을 읽고 내 가게(나이, 지역, 업종, 업력)가 해당하는지 판정한다. 결과는 "신청 가능성 높음 / 일부 확인 필요 / 판단 불가"로 나누고, 조건마다 근거가 된 공고문 문장을 함께 보여준다. 나이·업력 같은 숫자 조건 대조는 계산 도구가 하고, 명확히 맞지 않는 공고는 목록에서 빼고 건수만 알린다
- **AI가 요약**: 긴 공고문을 "누가, 얼마를, 언제까지, 무엇을 내면" 형태로 요약한다
- **화면**: **포스터 카드 그리드**(포스터 이미지·신청 가능성 배지·마감 D-day·요약·조건 칩)를 기본으로, 리스트와 마감 달력 보기를 고를 수 있다. 신청 가능성·분야(사업화·융자·공간·교육·멘토링)로 거르고 마감순·적합도순으로 정렬한다. 카드를 누르면 포스터 원본, 조건별 공고문 인용, 제출서류, 신청 링크, 제외된 공고 건수가 나온다
- **포스터**: 공고 응답에 이미지가 있으면 출처와 함께 보여 주고, 없으면 제목·기관·마감일로 만든 포스터형 카드로 대신한다
- **결과**: 마감일은 개업 체크리스트와 달력에 자동으로 들어간다

### 4-6. 알림 센터

알림은 읽고 끝나는 목록이 아니라 **바로 처리할 곳으로 이어지는 입구**다.

- **유형 탭**: 결정 필요(선택지를 아직 고르지 않은 카드) / 다음 할 일(카드를 실행·완료했을 때 자동 정리) / 마감 임박 / 변경 감지(다시 조회로 달라진 점, 마이페이지 수정 반영 기록) / 지원사업
- **액션 버튼**: 알림마다 "카드 열기", "체크리스트 열기", "지원사업 열기"처럼 이어질 곳이 붙는다
- **시점 이동(시연용)**: 지금 / 개업 D-7 / 개업 6개월 후로 시점을 옮겨 가며 "개업 후에도 먼저 알려준다"를 눌러 볼 수 있다. 시간이 지나야 생기는 알림은 모두 예시 배지가 붙고, 부가세 신고 기한 같은 정확한 날짜는 지어내지 않고 "국세청 안내로 확인하세요"로 둔다

### 4-7. AI 상담

- **쓰는 상황**: 결과를 보다가 궁금한 것을 물을 때, 개업일처럼 조건을 바꾸고 싶을 때, 구청에 전화하기 전에 준비할 때
- **답변 범위**: 이 가게에 저장된 근거(조회 결과, 조문, 공고문) 안에서만 답한다. 근거를 못 대면 "판단 불가"와 함께 **문의할 기관 전화번호**를 안내한다. 세금·4대보험 일정, 대출·금리, 법률 해석, 금액 계산은 답하지 않는다
- **근거 칩**: 답변 아래에 근거(건축물대장, 조문 등)가 칩으로 붙고, 누르면 리포트의 판정 근거 창이 열린다
- **확인 후 적용하는 제안 카드**: 개업일 변경, 선택지 적용("그럼 이걸로 할게요"), 체크리스트 완료 처리, 화면 이동을 제안한다. 카드에 **바뀌는 내용(전→후)을 먼저 보여 주고**, 사용자가 `[확인하고 적용]`을 눌러야 반영된다. 취소하면 아무것도 바뀌지 않는다. 개업일 변경은 체크리스트 날짜만 다시 계산하고, 주소·업종·답변 변경은 다시 분석한다
- **항목별 상담**: 리포트 카드의 "이 항목 질문하기"로 들어오면 그 카드가 대화 위에 고정되고 "왜 이런가요 / 안 하면 어떻게 되나요 / 다른 방법은 없나요 / 전화로 문의할 땐 뭐라고 하죠" 후속 질문이 나온다. 다른 주제를 물으면 고정된 카드에 갇히지 않고 그 주제로 답한다
- **상황별 추천 질문**: 결정 대기 카드, 개업까지 남은 기간, 고정한 카드에 따라 질문 칩이 바뀐다. 답변마다 후속 질문 칩이 붙는다
- **"오늘 뭐부터 하죠?"**: 결정할 것 1개와 직접 할 일 1개로 요약한다. 추천 선택지는 바로 적용 제안으로 붙는다
- **통화 준비 도우미**: "구청에 전화하기 전에 뭘 준비하죠?"라고 물으면 기관 번호, 30초 통화 순서, 꼭 물어볼 질문, 통화 후 메모란을 준다. 통화를 마치면 결과가 카드에 "문의했어요(답변 대기)"로 기록된다. 스크립트는 가게 정보와 조회 데이터로만 채우고 모르는 칸은 `[확인 필요]`로 둔다

### 4-8. 마이페이지

가게 정보를 "등록"하는 화면이 아니라 **내 계정과 가게를 관리하는 화면**이다. 첫 설정이 끝난 뒤 정보를 바꾸는 곳은 여기뿐이다.

- **구성**: 내 계정(이름, 로그인 방식, 로그아웃) / 가게 정보(이름, 업종, 주소·층, 개업일, 출생 연도) / 영업 조건(술 판매, 테라스, 직원, 준비 자금) / 최근 변경 반영 / 데이터 관리(가게 정보 처음부터 다시 설정)
- **영향 미리보기**: 값을 바꾸면 항목마다 "바뀌면 → 다시 반영되는 것"이 보이고, 저장 전에 **바꾼 내용 / 다시 반영되는 것 / 선택이 초기화되는 카드**를 한 번에 보여 준다
- **영향받는 것만 다시 반영**: 영향 범위는 규칙(코드)이 정한다

| 바꾼 것 | 다시 하는 일 |
| --- | --- |
| 개업 예정일 | 체크리스트 날짜만 재계산 (외부 조회 없음) |
| 가게 이름 | 상표 점검 |
| 주소·층, 업종, 술 판매 | 건물 용도·법령 점검, 체크리스트 항목 (상권 분석은 붙인 뒤) |
| 테라스, 직원 | 옥외영업 점검, 고용 카테고리 표시 |
| (마지막에 구현) 메뉴·광고 문구 | 광고 문구 점검 |
| 출생 연도 | 지원사업 자격 판정 |
| 준비 자금 | 비용·지원사업 계산 |

- **이미 고른 선택은 영향받는 카드만 초기화**한다. 예를 들어 주소를 바꾸면 건물 용도 카드에서 고른 "다른 자리 알아보기"가 지워지고 다시 결정 대기로 돌아간다. 데이터가 서로 어긋나지 않게 하려는 것이다. 카드가 초기화되면 그 카드로 생긴 체크리스트 항목과 자동 체크도 함께 풀리고, 직접 한 체크는 유지한다
- 저장하면 영향받는 단계만 "다시 반영 중" 진행 화면이 돌고, 끝나면 무엇이 바뀌었는지 요약과 변경 기록이 남는다 (알림 센터에도 "변경 감지"로 남는다)

## 5. 개업 후에도 계속 쓰는 서비스

저장된 **가게 정보**가 모든 메뉴의 중심이다. 사용자가 다시 찾아오지 않아도 서비스가 먼저 연락한다.

| 시기 | 기능 | 사용자가 돌아오는 이유 |
|---|---|---|
| 개업 직후 | 개업 후 30일·90일 체크리스트 (세무 신고 시작, 4대보험, 위생점검 대비) | 할 일이 가장 많고 놓치기 쉬운 때다 |
| 운영 중 | **반복 일정 관리**: 부가세·종합소득세 신고, 위생교육 갱신, 임대차 계약 만료 | 기한을 놓치면 과태료가 나온다 |
| 운영 중 | **법·정책 변경 알림**: 내 가게에 해당하는 개정만 골라 전달 | 찾아보지 않아도 알 수 있다 |
| 운영 중 | **상권 모니터링**: 새 경쟁 가게, 주변 가격 변동, 월 1회 상권 요약 (알림 센터의 시점 이동으로 시연) | 내 가게 주변 변화를 바로 안다 |
| 성장 | 2호점 상권 분석 | 상권 분석을 새 주소로 그대로 다시 쓴다 |
| 전환 | 폐업·양도 절차 안내 | 마지막 단계까지 함께한다 |

계속 쓰게 만드는 장치는 세 가지다: **① 저장된 가게 정보 ② 먼저 보내는 알림 ③ 월간 요약 리포트**

## 6. AI 에이전트 구조와 오류 대응

- **구조**: 조회는 코드에 고정된 순서(건축물대장 → 상표 → 법령 조문 → 지원사업 공고)로 하고, **AI 에이전트가 조회한 데이터를 읽고 판단·설명한다.** AI가 어떤 API를 부를지 고르는 구조(tool use)는 예선 이후 로드맵이다. 멀티 에이전트는 일정상 채택하지 않는다
- **판정 흐름**: 규칙 묶음이 업종별 점검 항목과 볼 조문을 정하고 → 코드가 API로 원문을 가져오고 → **AI가 조문·건축물대장·공고문·상표 목록을 읽고 이 가게에 해당하는지 판정**하고 → 코드가 AI가 인용한 용도·조문 문장·상표 번호가 원문에 실제로 있는지 검증한다 (검증 실패는 판단 불가)
- **카드별 판정 주체**: 건물 용도·위반건축물·영업신고 서류(조문 해석)·상표 유사·지원사업 자격 = **AI**, 표시 의무 = 읽을 근거가 없는 일반 안내(규칙). 업종 결정(술 → 일반음식점)만 규칙이고, 규칙표는 AI 판정을 대조하는 안전장치다 (AI와 규칙표가 어긋나면 "확인 권장"으로 낮추고, AI가 실패하면 규칙표 카드로 대체)
- **AI가 하는 일**: 되묻기, 조문·건축물대장을 읽고 건물 용도·해당 신고·인허가 판정, 상표 유사성 판단, 지원사업 자격 판정, 위험 판정, 공고문·조문 요약과 분류, **선택지 구성과 추천 이유, AI 상담 답변 문장**
- **AI가 도구에 맡기는 일**: 데이터 조회, 날짜·기한 계산, 금액 합산, 숫자 조건 대조 (AI가 직접 계산하지 않고 도구를 불러 결과를 받는다)
- **코드가 하는 일 (AI 아님)**: 마이페이지 수정의 영향 범위와 초기화할 카드 결정, 다음으로 할 일의 선택·정렬, 점검 카드와 체크리스트의 자동 체크, 서류 목록·받는 곳 링크 조립, 통화 질문 목록 조립, 기관 전화번호 조회, (마지막에 구현) 상권 지표와 가격 구간 계산, 알림 생성, 상담의 근거 첨부와 변경 제안 검증
- **판정의 조건**: AI는 조회한 데이터 안에서만 판정한다. 판정마다 근거가 된 조문·공고문 문장을 인용하고, 근거가 없으면 판정하지 않는다
- **해결안의 조건**: 선택지 종류는 업종 규칙 묶음에 정해 둔 범위 안에서만 만든다. 기간·금액은 근거(규칙·계산·데이터)가 있을 때만 숫자로 쓰고, 없으면 "확인 필요"로 표시한다

| 오류 대응 | 방법 |
|---|---|
| 근거 표시 | 모든 판단에 조문 원문·링크, 데이터 출처, 조회 일자를 붙인다 |
| 확신 정도 표시 | "위반 소지 높음 / 낮음 / 판단 불가"로 구분한다 |
| 모르면 보류 | 근거를 찾지 못하면 추측하지 않고 "판단 불가, 관할 기관 확인 필요"로 표시한다 |
| 중요 건 안내 | 계약·신고처럼 돈이 걸린 항목은 관할 기관 확인을 함께 안내한다 |

## 8. 확장성과 비용

### 확장이 쉬운 이유: 구조는 그대로, 규칙만 추가

- 에이전트와 조회 도구는 업종과 무관하게 공통으로 쓴다
- 업종마다 달라지는 것은 **규칙 묶음**(어떤 신고가 필요한지, 어떤 조문을 볼지, 무엇을 되물을지)뿐이다
- 새 업종 추가는 코드 수정이 아니라 규칙 묶음 하나를 더하는 작업이다. 프로토타입도 이 구조로 만든다

| 단계 | 대상 | 추가되는 것 |
|---|---|---|
| 1 (현재) | 카페·음식점 | 영업신고, 위생교육, 주류와 업종 구분, 원산지 표시, 간판 |
| 2 | 다른 매장형 업종 (미용실, 공방, 꽃집, 무인매장) | 업종별 면허·신고 |
| 3 | 온라인 판매자 | 통신판매업 신고, KC 인증, 상세페이지 문구 점검 |
| 4 | 청년 소상공인 전반 | 프랜차이즈 가맹 전 검증, 점검 사례 통계, 커뮤니티 |

### 비용과 운영

- 공공데이터 API는 무료이므로 변동 비용은 AI 호출뿐이다. 같은 공고·같은 조문에 대한 판정 결과는 저장해 두고 다시 써서 호출을 줄인다
- 같은 건물·같은 조문·같은 공고의 조회 결과는 저장해 두고 다시 쓴다
- 되묻기 같은 단순 단계는 저렴한 모델로, 최종 해석만 상위 모델로 처리한다
- 조문과 공고는 저장해 두지 않고 매번 조회하므로 최신 상태가 유지된다. 사람이 관리할 것은 업종별 규칙 묶음뿐이다
- 비교 대상은 행정사·세무사 상담료와, 영업신고 반려로 날리는 월세·보증금이다. 점검 1회 비용을 실제로 측정해 나란히 제시한다
- 지자체 청년창업센터, 소상공인시장진흥공단과 연계하면 사용자 확보와 규칙 검수를 함께 해결할 수 있다

## 11. 검증 방법

- 배포 URL 접속 → 로그인 화면에서 "예시 계정으로 둘러보기"(이서연 씨 사례)로 대시보드가 끝까지 채워지는지 확인
- 새 계정으로 회원가입·로그인 → 첫 설정 → 홈까지 이어지는지, 다른 계정으로 바꾸면 가게·점검 결과·체크리스트가 섞이지 않는지 확인
- 위반건축물 주소, 등록 상표와 겹치는 이름, 휴게음식점 + 주류 메뉴 등 문제 사례를 넣어 각각 잡아내는지 확인
- 문제 항목마다 결론·선택지·추천·기관 전화번호·사용자가 할 일 1개가 나오는지, `[추천대로 진행]`을 누르면 가게 정보와 체크리스트가 바뀌는지 확인
- 선택지의 금액·기간이 근거 없이 숫자로 나오지 않는지(없으면 "확인 필요"), 확인하지 못한 전화번호가 "예시"로 표시되는지 확인
- 점검 카드에서 "문의했어요"·"완료"를 누르면 다음으로 할 일이 카드 안에 생기고 알림 센터에 "다음 할 일"이 남는지, 카드를 완료하면 연결된 체크리스트 항목이 자동 체크되는지(카드 2개가 연결된 항목은 둘 다 완료해야), 카드를 되돌리면 자동 체크만 풀리는지 확인
- 마이페이지에서 개업일만 바꾸면 체크리스트 날짜만 바뀌는지, 주소·술 판매를 바꾸면 영향받는 카드만 초기화되고 저장 전에 미리 보이는지, 직원 유무에 따라 고용 카테고리가 나타나고 사라지는지 확인
- 체크리스트 항목마다 필요 서류와 받는 곳이 나오는지, 서류함 요약 숫자가 체크리스트 완료와 맞는지, 받는 곳 링크가 새 탭으로 **올바른 공식 사이트**에 열리는지(사람이 한 번씩 눌러 확인), 서류를 만들어 주는 버튼이 없는지 확인
- 체크리스트 달력에서 기한·개업일·지원사업 마감이 보이고 `.ics`로 내보내지는지, 알림 센터의 시점 이동에서 개업 후 알림이 예시 배지와 함께 나오는지 확인
- AI 상담에서 근거 칩이 붙는지, 변경 제안이 확인 전에는 반영되지 않는지, 범위 밖 질문에 판단 불가와 기관 전화번호가 나오는지, 통화 준비 결과가 카드에 기록되는지 확인
- (마지막에 구현) 상권 분석에서 지도 마커·경쟁 강도·가격 포지셔닝이 나오고 데이터 없는 지표를 지어내지 않는지, 예시 데이터에 예시 배지가 붙는지 확인
- 근거 조문 링크가 실제 조문으로 연결되는지, 항목마다 출처와 조회 일자가 표시되는지 확인
