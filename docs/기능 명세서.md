## 1. 서비스 한 줄과 확정 범위

**어디에서 사업을 할지 이미 정한** 카페·음식점 청년 창업가가 주소·업종·개업일을 한 번 입력하면, 건축물대장·법령·상표를 조회해 **점검 리포트**와 **개업 체크리스트**를 만들고, 문제가 나온 항목은 **결정 → 실행 → 완료**까지 이어가게 돕는 창업 전 사전 점검 서비스.

### 확정된 기능 (메뉴 7개 + AI 상담)

| 메뉴 | 한 줄 | 장 |
| --- | --- | --- |
| 로그인 | 소셜 로그인(카카오·Google·네이버, 시연용 UI)과 예시 계정 | 3 |
| 첫 설정 | 가게 정보 입력 → 되묻기 → 조사 중 | 4 |
| 내 가게 홈 | 결정할 것·직접 할 일·다음 할 일·새 알림 | 5 |

| 제외 | 이유·처리 |
| --- | --- |
| **상권 분석** (지도, 경쟁 강도, 가격 포지셔닝) | **마지막에 구현해 붙인다.** 프로토타입의 "상권 분석" 메뉴는 시연용 자리표시다. 다른 기능은 상권 분석에 의존하지 않는다 |
| **메뉴·광고 문구 점검** | 입력란과 카드가 프로토타입에 없다. 마지막에 구현 |

| 입지 추천·후보 상권 비교·후보 자리 직접 입력·매물 비교 | 입지를 정한 사용자만 대상이다 |
| 대출 안내, 다른 업종 | 범위 밖 |

## 2. 공통 규칙

### 2-1. 판정과 근거

| 판정 값 | 화면 표시 | 의미 |
| --- | --- | --- |
| `high` | 위반 소지 높음 | **규칙**이 데이터로 확인한 경우만 |
| `low` | 확인 권장 | AI 판단이거나 데이터가 일부만 있음 (AI 판정의 상한) |
| `unknown` | 판단 불가 | 근거를 찾지 못함 → 관할 기관 확인 안내 |
| `ok` | 문제 없음 | 통과 (접어서 표시) |

- 모든 리포트 항목에는 **근거**(데이터 원값 또는 조문 + 출처·조회 일자·링크)가 있어야 한다. 근거가 없으면 `unknown`이고 판단을 지어내지 않는다. ("판정 근거 자세히" 창에서 본다)
- 모의 응답을 쓴 근거에는 "모의 응답" 표시가 붙는다.
- 규칙·계산으로 정할 수 있는 것은 **코드**가 한다 (업종 결정, 건물 용도, 날짜, 영향 범위, 다음 할 일, 자동 체크, 전화번호, 서류 목록·링크). **AI**는 쉬운 말 설명, 추천 이유, 상표 유사성 판단, 상담 답변만 한다.

### 2-2. 기관 전화번호

- 관할 구청 건축과·위생과, 국세상담센터(126), 고용노동부 상담센터(1350), 정부민원안내콜센터(110)가 있다.
- 전화번호는 AI가 만들지 않고 규칙 묶음에서만 가져온다. 확인하지 못한 번호(구청)는 **"예시"** 배지를 붙인다. 번호는 복사할 수 있다.

### 2-3. 예시 데이터 표시

- 시점 이동 알림과 지원사업 일부 알림은 `예시` 배지를 붙인다. 지원사업 공고는 "(예시 공고)"로 표시한다.
- 모든 화면에서 "법률 자문이 아닌 사전 점검" 안내를 유지한다.

### 2-4. 화면 틀

- 상단: 로고, 알림 종 아이콘(안 읽은 수 배지, 누르면 알림 미리보기), 가게 바로가기, 로그아웃.
- 메뉴(순서): **내 가게 홈 · 점검 리포트 · 체크리스트 · 서류함 · 지원사업 · 상권 분석(자리표시) · 마이페이지**.
- 우하단 **AI 상담** 버튼 → 상담 패널.
- 가게 정보가 없는 계정은 메뉴 대신 첫 설정만 보인다. 로그인하지 않으면 로그인 화면만 보인다.
- 디자인: 주 색상 `#107e7d`, 흰 배경, 카드는 연한 회색. 모바일 폭에서 메뉴는 가로 스크롤.

## 3. 로그인과 계정

- **소셜 로그인 버튼 3개**(카카오·Google·네이버). 누르면 "○○ 계정으로 계속하기" 창에서 이름을 입력해 들어간다 (프로토타입은 시연용, 실제 OAuth 연결은 마지막).
- **예시 계정으로 둘러보기**: 가입 없이 이서연 씨 사례가 채워진 채로 열린다 (5장 시연 값).
- **계정별 데이터 분리**: 가게·점검 결과·체크리스트·알림이 계정마다 따로 저장된다. 다른 계정으로 로그인하면 완전히 다른 가게가 나오고, 같은 계정으로 다시 들어오면 데이터가 남아 있다.
- 로그아웃하면 진행 중이던 비동기 작업(분석 진행 등)을 모두 취소한다.
- **한 계정 = 가게 하나.**

## 4. 첫 설정 (가게 등록)

로그인했는데 가게가 없으면 시작한다. 3단계: **가게 정보 → 영업 조건 → 조사 중**.

### 4-1. 가게 정보 (1단계)

| 입력 | 필수 | 비고 |
| --- | --- | --- |
| 가게 이름 | O | 상표 검색에 쓴다 |
| 업종 | O | 카페·음식점 |
| 주소 | O | 입지를 정한 주소. 비면 진행하지 않는다 |
| 층·호 | | 건축물대장 층별 조회에 쓴다 |
| 개업 예정일 | O | 체크리스트 역산 기준 |
| 출생 연도 | | 지원사업 자격 판정에만 쓴다 |

- 예시 가게를 불러오는 **시연 안내 배너**(이서연 씨 사례)가 있다.

### 4-2. 영업 조건 (2단계, 되묻기)

판단에 필요한 것만 묻는다. 각 질문에 **왜 묻는지** 한 줄이 붙는다.

| 질문 | 왜 필요한가 | 영향 |
| --- | --- | --- |
| 술도 판매하시나요? | 술을 팔면 신고 업종이 휴게음식점 → 일반음식점으로 바뀐다 | 건물 용도·영업신고 |
| 테라스나 가게 앞 공간을 사용하시나요? | 옥외영업 관련 확인이 필요할 수 있다 | 법령·체크리스트 |
| 직원을 고용하시나요? | 근로계약·4대보험 일정이 생긴다 | 고용 카테고리 |
| 준비 자금 (선택) | 지원사업·비용 계산 | 지원사업 |

### 4-3. 조사 중 (3단계)

진행 단계를 하나씩 체크 표시로 보여 준다 (조회 → 판정 → 체크리스트).

| 순서 | 단계 |
| --- | --- |
| 1 | 주소 확인 |
| 2 | 건축물대장 조회 |
| 3 | 상표 검색 |
| 4 | 조문 조회 |
| 5 | 규칙 판정 |
| 6 | AI 판정 |
| 7 | 선택지·추천 생성 |
| 8 | 개업일 역산 체크리스트 |

(주변 동종 업소 조회는 상권 분석을 붙일 때 추가한다.) 끝나면 내 가게 홈으로 이동한다. 도구가 실패하면 해당 항목만 `판단 불가`로 두고 끝까지 진행하며, 캐시·모의 응답을 쓰면 `fallback`으로 표시한다.

## 5. 내 가게 홈

첫 화면. 가게 요약(이름·업종·주소·개업일, D-day)과 지표 3개, 아래 두 영역.

| 지표 | 내용 |
| --- | --- |
| 결정 시한 | 아직 선택하지 않은 카드 수 |
| 체크리스트 | 완료/전체 (예: 2/9) |
| 새 알림 | 안 읽은 알림 수 |

| 영역 | 내용 |
| --- | --- |
| **결정할 것** | 선택지가 있는데 아직 고르지 않은 카드. 판정 배지·단계·추천 표시, `[카드 열기]` |
| **내가 직접 할 일** | 사용자가 직접 해야 하는 일 (카드의 할 일 + 가까운 체크리스트 4개). 항목마다 소요 시간·기관·전화번호, `[열기]` |

- "~를 확인하세요"로 끝내지 않고 "구청 건축과에 전화로 문의하기 (3분)"처럼 구체적인 행동으로 쓴다.
- 서류함 요약(전체 서류·완료한 항목의 서류·남은 서류)과 함께 본다 (서류함 8장).

## 6. 점검 리포트

### 6-1. 카드 5장 (규칙 묶음이 순서를 정한다)

| 번호 | 점검 항목 | 시기 | 판정 | 결정 방식 | 선택지 | 기관 |
| --- | --- | --- | --- | --- | --- | --- |
| r-01 | 건물 용도·주류 | 계약 전 | 술 판매 → `high`, 아니면 `ok` | AI(규칙표 대조) | ① 술 빼고 카페로 시작 ② 용도변경 신청 ③ 다른 자리를 알아보기 | 구청 건축과 |
| r-02 | 상호·상표 유사 | 계약 전 | `low` | AI | ① 이름 바꾸기(겹치지 않는 후보) ② 그대로 진행 | — |
| r-03 | 위반건축물 | 계약 전 | `unknown` (대장 응답에 표기 없음) | AI | 없음 | 구청 건축과 |
| r-04 | 영업신고 서류 | 개업 전 | `low`(조문을 읽은 AI 판정) | AI(조문 근거) | 없음 | 구청 위생과 |
| r-05 | 기본 표시 의무 | 운영 중 | `ok` (일반 안내, 점검 결과 아님) | 규칙 | 없음 | — |

- 위험한 것부터 정렬한다. 후속 행동을 마치기 전에는 원래 판정 자리에 두어 카드가 튀지 않는다.
- 상단 필터로 판정별로 거른다. 문제가 없는 카드(`ok`)는 접어서 보여 준다.

### 6-2. 카드 구성 (문제 항목)

| 칸 | 내용 |
| --- | --- |
| 결론 | 한 줄, 쉬운 말 ("이 자리에서는 술을 팔 수 없어요") |
| 이유 | 한두 문장 |
| 안 하면 생기는 일 | 돈·시간 기준 |
| 선택지 | 비교 카드. 기간·금액은 **근거가 있을 때만** 숫자, 없으면 "확인 필요". 고르기 전에 "적용하면 이렇게 바뀌어요"를 미리 보여 주고 확정 창으로 확인한다 |
| 추천 | 기본 선택 하나와 이유 (`[추천대로 진행]`) |
| 기관 전화번호 | 문의할 곳과 번호 (예시 배지, 복사) |
| 사용자가 할 일 1개 | 유형(문의·서명·방문·결정)과 소요 시간 |
| 판정 근거 자세히 | 출처·값·조문·링크·조회 일자 창 |
| 이 항목 질문하기 | AI 상담을 이 카드에 고정해 연다 |

### 6-3. 결정 → 실행 → 완료

| 단계 | 화면 | 하는 일 |
| --- | --- | --- |
| 결정 | 선택지 비교, 추천 | 하나를 고른다. 선택은 언제든 **되돌릴 수 있다** (선택 변경) |
| 실행 | 적용한 방법, 바뀐 내용, 내가 할 일 | 가게 정보 before→after, 체크리스트 추가·변경, 판정 변화(위반 소지 높음 → 문제 없음)를 보여 준다. 사용자가 전화하고 **"문의했어요"**를 누르면 답변 대기가 된다 |
| 완료 | 결과 메모 | 통화 결과를 메모하고 **완료**로 기록한다. 완료는 되돌릴 수 있다 |

- 선택지가 없는 카드는 결정 단계가 끝난 것으로 보고 실행부터 시작한다.
- **선택의 효과**: "술 빼고 시작"은 가게 원본 값을 바꾸지 않고 카드에 효과로 붙어 **유효 값**(술 판매 안 함)이 된다. 점검 문구·체크리스트 제목·업종이 유효 값 기준으로 바뀌고, 카드를 초기화하면 원본으로 돌아간다. "이름 바꾸기"도 같다.
- **선택으로 생기는 체크리스트 항목**: ③ 다른 자리 → "용도가 맞는 다른 후보 자리 알아보기", ② 용도변경 → "구청 건축과에 용도변경 가능 여부 문의", 상표 ② 그대로 진행 → "간판 제작 전 상표 최종 확인(KIPRIS)". 선택을 되돌리면 사라진다.
- 서비스는 문자 발송·정부24 제출을 대신하지 않는다. 사용자가 직접 한 뒤 상태만 기록한다.

### 6-4. 다음으로 할 일 (자동 정리)

"문의했어요"나 "완료"를 누르는 순간 그 카드 안에 생긴다. **최대 5개**, 코드가 정렬한다 (AI 아님).

| 순서 | 종류 | 내용 |
| --- | --- | --- |
| 1 | 새로 생긴 할 일 | 이번 선택으로 체크리스트에 새로 생긴 항목 (`새로 생김` 배지) |
| 2 | 결정하기 | 아직 선택하지 않은 카드 (위반 소지 높음 먼저, 추천 표시) |
| 3 | 직접 할 일 | 다른 카드의 할 일 (선택을 마쳤고 아직 안 한 것) |
| 4 | 체크리스트 | 아직 안 끝난 항목 중 기한이 빠른 2개 (기한·기관·전화번호) |

- 항목마다 바로 가는 버튼(`카드 열기`·`체크리스트 열기`)이 있다. "문의했어요" 단계에서는 "답변을 기다리는 동안 먼저 하세요"로 보여 준다.
- 모두 끝났으면 "점검 리포트의 모든 항목을 마쳤어요"를 보여 준다.
- 같은 내용이 알림 센터에 **다음 할 일**로 남는다 (카드를 되돌리면 사라진다).

### 6-5. 체크리스트 자동 체크

점검 카드와 같은 일인 체크리스트 항목은 **카드를 완료하면 자동으로 체크**된다. 카드와 체크리스트 양쪽에 "연동됨" 표시가 나온다.

| 체크리스트 항목 | 연결된 카드 |
| --- | --- |
| c-01 건축물대장 확인·임대차 계약 검토 | r-01 **그리고** r-03 (둘 다 완료해야) |
| c-02 상호·상표 확인 | r-02 |
| c-04 영업신고 서류 준비 | r-04 |
| x-0, x-1 (선택으로 생긴 항목) | r-01 |
| x-2 | r-02 |

- 카드를 되돌리면 **자동 체크된 항목만** 풀리고, 사용자가 직접 한 체크는 유지한다. 방향은 한쪽이다 (체크리스트를 먼저 체크해도 카드는 완료되지 않는다).

## 7. 개업 체크리스트

개업 예정일에서 거꾸로 계산한 일정. 항목마다 완료 체크, D-day, 기한, 담당 기관(전화번호), 필요 서류가 붙는다.

### 7-1. 기본 항목 (9개, 시기·오프셋 고정)

| 번호 | 항목 | 카테고리 | 시기 | 개업일 기준 | 담당 기관 |
| --- | --- | --- | --- | --- | --- |
| c-01 | 건축물대장 확인 및 임대차 계약 검토 | 건물·시설 | 계약 전 | -56일 | 관할 구청 건축과 |
| c-02 | 상호·상표 유사 여부 추가 확인 | 간판·광고 | 계약 전 | -49일 | KIPRIS |
| c-03 | 사업자등록 신청 | 세무 | 개업 4주 전 | -28일 | 홈택스 또는 세무서 |
| c-04 | (일반음식점/휴게음식점) 영업신고에 필요한 서류 준비 | 영업 인허가 | 개업 4주 전 | -28일 | 관할 구청 위생과 |
| c-05 | 식품위생교육 이수 | 영업 인허가 | 개업 4주 전 | -22일 | 관련 교육기관 |
| c-06 | 건강진단결과서 준비 | 영업 인허가 | 개업 직전 | -10일 | 보건소 등 |
| c-07 | 간판 설치 관련 기준 확인 | 간판·광고 | 개업 직전 | -6일 | 관할 구청 |
| c-08 | 근로계약서 및 고용 관련 사항 확인 | 고용 | 개업 직전 | -3일 | 고용노동부 안내 (**직원을 고용할 때만 표시**) |
| c-09 | 운영 중 표시 의무 사항 점검 | 표시 의무 | 개업 후 | +7일 | 관할 기관 |

- 날짜는 **계산 도구**가 `개업일 + 오프셋`으로 계산한다 (AI는 날짜를 계산하지 않는다). 시기(`계약 전`/`개업 4주 전`/`개업 직전`/`개업 후`)는 항목마다 정해 둔 값이다.
- c-04 제목 앞에 붙는 업종은 유효 값(술 판매 여부)으로 정한다.
- 선택으로 생기는 항목: x-0(-70일), x-1(-60일), x-2(-30일), 모두 계약 전. 선택을 되돌리면 사라진다.
- 사용자의 조건에 맞지 않는 카테고리(직원 없음 → 고용)는 숨긴다.

### 7-2. 보기

| 보기 | 내용 |
| --- | --- |
| 시기별 | 4개 시기 그룹, 그룹 안 기한순 |
| 카테고리별 | 영업 인허가·세무·고용·건물·시설·간판·광고·표시 의무·정책 (카테고리 색) |
| 달력 | 월 달력에 기한을 카테고리 색 점으로, 개업일은 깃발로 표시. 날짜를 누르면 옆 패널에 그날 할 일이 나오고 거기서 바로 체크. 이전·다음 달, 지원사업 마감 표시 |

- 항목마다 `D-n`(지난 날은 `D+n`), 기한, 담당 기관, **필요 서류 수**, 연동된 점검 카드 표시. 서류가 있는 항목은 서류함으로 이동 링크.
- 완료 체크는 새로 고침 후에도 유지된다.
- **`.ics` 내보내기**: 체크리스트를 캘린더 파일로 내려받아 구글·애플 캘린더에 넣는다.

### 7-3. 개업일 변경

마이페이지·AI 상담·알림에서 개업일을 바꾸면 **체크리스트 날짜만 다시 계산**한다 (외부 조회·AI 호출 없음). 바뀐 첫 날짜 변경 예시를 확인 창에서 미리 보여 준다.

## 8. 서류함

신고·신청에 필요한 서류를 **어디서 받는지**만 안내하는 읽기 전용 화면. 서류를 대신 만들지 않고, 서류별 준비 체크도 없다.

- 요약: **전체 서류**(8개) · **완료한 항목의 서류** · **아직 남은 서류**. 완료는 체크리스트 항목 완료로 센다.
- 체크리스트 항목별 카드(기한순). 카드에 항목명·시기·예정일·D-day, 아래에 서류 목록.
- 서류마다: **서류 이름 · 받는 곳 · 찾는 방법(한두 문장) · 공식 사이트 링크 버튼**(새 탭), 필요하면 **기관 전화번호**(복사).

| 항목 | 서류 | 받는 곳 (공식 사이트 첫 화면) |
| --- | --- | --- |
| c-01 | 건축물대장(일반·집합) | 정부24, 세움터 |
| c-02 | 상표 검색 결과 | KIPRIS |
| c-03 | 사업자등록 신청 | 홈택스 |
| c-04 | 영업신고 접수 | 정부24 (+ 구청 위생과 전화번호) |
| c-07 | 옥외광고물 신고·허가 안내 | 정부24 (+ 구청 전화번호) |
| c-08 | 표준 근로계약서 양식 / 4대보험 취득 신고 | 고용노동부 / 4대사회보험 정보연계센터 |

- **링크는 사람이 확인한 공식 사이트의 첫 화면 주소만** 쓴다. 세부 신청 페이지 주소는 바뀌기 쉬워 쓰지 않는다. 찾는 방법은 안내 문구로 준다. 배포 전에 사람이 링크를 눌러 확인한다.
- 위생교육 기관·건강진단(보건소)은 발급처를 확정하지 못해 서류 항목이 없다 (체크리스트 항목과 기관 전화번호만 있다).
- 안내 문구: "정부 서식은 해당 사이트에서만 효력이 있어요. 발급·제출은 직접 해야 해요."
- 지원사업 상세에서도 K-Startup·기업마당 공식 사이트로 연결한다.

## 9. 지원사업

### 9-1. 목록

- **카드 그리드**(기본): 포스터형 카드(제목·기관·마감으로 생성한 포스터), **신청 가능성 배지**, 마감 D-day, 누가/얼마/언제까지/제출물 요약, 조건 칩(통과/확인 필요).
- 보기 전환: **카드 / 리스트 / 마감 달력(월별)**.
- 필터: 신청 가능성(전체·가능성 높음·일부 확인·판단 불가), 분야(사업화·융자·공간·교육·멘토링). 정렬: **마감순 / 적합도순**.
- 제외된 공고 수(조건이 명확히 맞지 않아 뺀 공고)를 요약에 보여 준다.

### 9-2. 자격 판정

| 값 | 화면 표시 | 의미 |
| --- | --- | --- |
| `eligible` | 신청 가능성 높음 | 확인된 조건이 모두 충족 |
| `partial` | 일부 확인 필요 | 충족한 조건이 있고 확인하지 못한 조건이 남음 |
| `unknown` | 판단 불가 | 근거 부족. 공고문 원문·주관 기관 확인 안내 |

- 판정은 **공고문 안에서** 하고 조건마다 공고문 문장을 인용한다. 근거가 없는 조건은 `unknown`이다. 나이(출생 연도)·업력 대조는 계산 도구가 한다.
- 시연 공고(예시): 청년 예비창업자 사업화 지원(최대 1,500만원), 청년 소상공인 점포 임차 지원(서울, 월 최대 50만원), 청년 창업 저금리 융자(최대 5천만원), 창업 기초 교육 과정, 지역 소상공인 멘토링.

### 9-3. 상세 창

대상·지원 내용·마감·제출서류, **조건별 판정과 공고문 인용**, K-Startup·기업마당 공식 사이트 링크.

## 11. AI 상담

우하단 버튼으로 여는 패널. **이 가게의 점검 결과·체크리스트·가게 정보 안에서만** 답한다.

### 11-1. 답변 종류

| 종류 | 화면 | 내용 |
| --- | --- | --- |
| 근거 기반 | "근거 기반" 배지 + **근거 칩** | 답에 쓴 항목의 근거를 칩으로 붙이고, 누르면 점검 리포트의 판정 근거 창이 열린다 |
| 변경 제안 | "변경 제안" 배지 + 전→후 미리보기 + `[확인하고 적용]` | 개업일 변경, 답변(술·직원·테라스·자금) 변경, 선택지 적용, 체크리스트 완료. **확인하기 전에는 아무것도 바뀌지 않는다.** 취소할 수 있다 |
| 판단 불가 | "판단 불가" 배지 + 문의할 기관 전화번호 | 세금·4대보험 신고 일정·대출·법률 해석처럼 근거 밖 질문 |
| 인사 | 배지 없음 | 인사·감사 |

- 근거(Evidence)는 AI가 쓰지 않고 **AI가 고른 항목 id의 근거를 코드가 붙인다.** 근거를 댈 수 없는 사실 답변은 "이 가게의 점검 결과로는 알 수 없어요"로 바꾼다.
- 변경 제안은 최대 2개, 값과 id는 코드가 검증한다 (과거 날짜·없는 항목 id는 버린다).

### 11-2. 기능 목록

| 기능 | 설명 |
| --- | --- |
| 추천 질문 | 가게 상태(결정 대기 카드, 개업까지 남은 일수, 고정된 항목)로 고른다. 첫 화면에 보인다 |
| **오늘 뭐부터 하죠?** | 결정할 것 1개와 직접 할 일 1개를 요약하고, 추천 선택지를 `[선택지 적용 제안]`으로 붙인다 (정렬은 코드) |
| **항목 고정(focus)** | 카드·체크리스트 항목의 "이 항목 질문하기"로 열면 그 항목이 대화 위에 고정된다. 다른 주제를 물으면 고정에 갇히지 않고 전체 근거에서 답한다. 후속 질문(왜 이런가요 / 안 하면 어떻게 되나요 / 다른 방법은 / 전화로 문의할 땐) |
| **통화 준비 도우미** | "구청에 전화하기 전에 뭘 준비하죠?" → 기관 이름·번호(복사), **통화 순서**, **꼭 물어볼 질문 목록**(점검 항목별 질문). 통화 뒤 **결과 메모**를 저장하면 카드가 "문의했어요(답변 대기)"로 기록된다 (선택지를 먼저 골라야 하는 카드는 메모만 저장) |
| 서류 질문 | "영업신고에 필요한 서류가 뭐예요?" → 서류 목록·받는 곳·찾는 방법·전화번호를 답하고 서류함으로 이동 제안. 서류 작성·제출을 대신한다고 답하지 않는다 |
| 날짜 변경 | "개업일을 4월 1일로 미루고 싶어요" → 체크리스트 날짜 변경 미리보기 제안 |
| 화면 이동 | 점검 리포트·체크리스트·서류함·지원사업·마이페이지로 이동 제안 (확인 불필요) |

- 프로토타입의 상담은 **규칙 기반 시뮬레이션**이다. 실제 LLM 연결 시 위 동작을 그대로 지킨다 (`AI_모듈_연동_가이드.md` 4-7).
- 대화 기록은 서버에 저장하지 않고 프론트가 매번 보낸다. 대화 안의 "규칙을 무시해" 같은 지시는 따르지 않는다.

## 12. 마이페이지

가게를 "등록"하는 화면이 아니라 **내 계정과 가게를 관리하는 화면**이다. 첫 설정 이후 정보를 바꾸는 곳은 여기뿐이다.

### 12-1. 구성

| 영역 | 내용 |
| --- | --- |
| 내 계정 | 이름(수정 가능), 로그인 방식, 로그아웃 |
| 가게 정보 | 이름·업종·주소·층·개업일·출생 연도 |
| 영업 조건 | 술 판매, 테라스, 직원, 준비 자금 |
| 영향 안내 | 항목마다 "바뀌면 → 다시 반영되는 것" |
| 최근 변경 반영 | 변경 기록 (최근 10건) |
| 데이터 관리 | **가게 정보 처음부터 다시 설정** (계정은 남기고 가게 데이터를 지움, 확인 창) |

- 마이페이지는 선택이 적용된 **유효 값**을 보여 준다 (예: "술 빼고 시작"을 골랐으면 술 판매 안 함).
- 주소를 비우면 저장할 수 없다.

### 12-2. 영향 분석과 다시 반영

값을 바꾸면 **저장 전에** 한 번에 보여 준다: 바꾼 내용 / 다시 반영되는 것 / 선택이 초기화되는 카드. 영향 범위는 규칙(코드)이 정한다.

| 바꾼 것 | 다시 하는 일 | 초기화되는 카드 |
| --- | --- | --- |
| 개업 예정일 | 체크리스트 날짜만 재계산 (외부 조회 없음) | 없음 |
| 가게 이름 | 상표 점검 | r-02 |
| 주소, 업종, 술 판매 | 건물 용도·법령 점검, 체크리스트 항목 | r-01, r-03, r-04 |
| 층·호 | 건물 용도 점검 | r-01, r-03 |
| 테라스 | 옥외영업 점검, 체크리스트 | r-01, r-04 |
| 직원 | 고용 카테고리 표시 | 없음 |
| 출생 연도 | 지원사업 자격 판정 | 없음 |
| 준비 자금 | 비용 계산 | 없음 |

- **영향받는 카드의 이미 고른 선택은 초기화**한다 (다시 결정 대기). 그 카드로 생긴 체크리스트 항목과 자동 체크도 풀리고, 직접 한 체크는 유지한다. 해당 카드의 "다음 할 일" 알림도 지운다.
- 저장하면 **진행 창**("변경 내용을 다시 반영하고 있어요")이 단계별로 보이고, 변경 기록과 알림(`변경 감지`)이 남는다. 저장 후 토스트 안내.
- 개업일만 바꾸면 날짜만 다시 계산한다.

## 13. 규칙·계산·AI 분담 요약

핵심 원칙: **AI는 조회한 데이터를 읽고 판단한다. 틀리면 치명적인 것은 규칙표로 대조하고, AI가 쓴 근거는 코드가 검증한다.**

### 13-1. 처리 흐름

```text
입력(업종·주소·개업일·영업 조건)
  ① 규칙 묶음이 "이 업종에서 볼 점검 항목"과 항목별로 볼 조문을 불러온다            (코드)
  ② API로 데이터를 조회한다: 건축물대장, 상표(KIPRIS), 법령 조문 원문, 지원사업 공고  (코드, 고정 순서)
  ③ AI가 조회한 데이터를 읽고 판정한다                                              (AI)
       건물 용도(대장의 층 용도 + 조문), 위반건축물(대장 표기), 영업신고 조문 해석,
       상표 유사성, 지원사업 자격
  ④ 코드가 AI의 인용을 검증한다                                                    (코드)
       인용한 건물 용도가 대장에 있는지, 인용한 조문·문장이 원문에 있는지, 상표 번호가 목록에 있는지
       → 검증 실패 = 판단 불가. 위반 소지 높음은 AI와 규칙표가 일치하고 근거가 검증될 때만 나온다
  ⑤ 문제 카드에 선택지·추천 이유를 AI가 쓰고, 선택 적용·체크리스트·연락처는 코드가 조립    (AI + 코드)
```

### 13-2. 카드별 판정 주체

| 카드 | 판정 | 판정에 쓰는 데이터 | AI가 하는 일 | 규칙·코드가 하는 일 |
| --- | --- | --- | --- | --- |
| r-01 건물 용도·주류 | **AI** | 건축물대장 층 용도, 건축법 시행령 별표 1 | 이 층 용도로 신고 업종이 가능한지 판정, 가능한 업종(술 빼고 시작 가능 여부) 판단 | 인용 검증, **규칙표 대조(어긋나면 확인 권장)**, AI 실패 시 규칙표 카드 |
| r-02 상표 유사 | **AI** | KIPRIS 유사 상표 목록 | 비슷한지 판단, 대체 이름 제안 | 인용한 상표 번호 검증 |
| r-03 위반건축물 | **AI** | 건축물대장 위반건축물 표기 | 표기를 읽고 판정 (표기 정보가 없으면 AI를 부르지 않고 판단 불가) | 표기 값과 다른 판정은 쓰지 않음, 연락처 |
| r-04 영업신고 서류 | **AI** | 조회한 식품위생법 등 조문 원문 | 조문을 읽고 이 가게에 해당하는 개업 전 할 일을 판정 | 인용 조문·문장 검증, 연락처·할 일 문장 |
| r-05 표시 의무 | 규칙 | 읽을 근거 데이터 없음 | — | 일반 안내 카드 (근거가 없어 `판단 불가`) |

### 13-3. AI가 하는 일 / 코드가 하는 일

| 일 | 주체 |
| --- | --- |
| 업종 결정(술 → 일반음식점) | 규칙 묶음 (법에 명시된 구분, AI 판정의 입력값) |
| **건물 용도, 위반건축물, 영업신고 조문 해석, 상표 유사성, 지원사업 자격 판정** | **AI** (조회한 데이터 안에서, 근거 인용 필수) |
| 선택지 설명·추천 이유, 상담 답변 문장 | AI |
| AI가 인용한 근거의 사실 확인, AI·규칙표 대조 | 코드 |
| 개업일 역산 날짜, 지원사업 마감 시기 | 계산 도구 |
| 선택지의 종류, 선택 적용(효과·체크리스트 추가) | 규칙 묶음 + 코드 |
| 영향 범위·초기화할 카드, 다음 할 일, 자동 체크, 알림 생성 | 코드 |
| 기관 전화번호, 서류 목록·링크, 통화 질문 | 규칙 묶음 (AI가 만들지 않음) |
| 상담의 근거 첨부·변경 제안 검증 | 코드 |

### 13-4. 안전장치와 한계

- AI가 실패하거나(3회 연속 실패 포함) 읽을 데이터가 없으면 해당 카드는 규칙표·안내 카드로 대체되고(`ai_fallback`), 진행 화면에 `fallback`이 표시된다. 시연은 멈추지 않는다.
- 근거를 검증하지 못한 AI 판정은 `판단 불가`다. 판단을 지어내지 않는다.
- 규칙표(업종별 허용 건물 용도)는 AI 판정을 대조하는 안전장치다. AI와 규칙표가 위반 소지 높음·문제 없음에서 어긋나면 확인 권장으로 낮추고, 규칙표로 확인되지 않은 AI의 위반 소지 높음도 확인 권장으로 낮춘다. AI 판정이 `high`가 될 수 있는 카드는 건물 용도·위반건축물뿐이다.
- **조회할 데이터의 선택(어떤 API를 부를지)은 AI가 아니라 코드에 고정된 순서다.** AI가 도구를 고르는 구조(tool use)는 예선 이후 로드맵이다.

## 15. 데모 시나리오와 수용 기준

| # | 시나리오 | 기대 결과 |
| --- | --- | --- |
| S1 | 휴게음식점 용도 층 + 주류 판매 | r-01 `위반 소지 높음`, 선택지 3개·추천·기관 전화번호·할 일 1개. 실행 → 완료하면 다음 할 일 정리, r-03까지 완료 시 c-01 자동 체크 |
| S2 | 등록 상표와 비슷한 가게 이름 | r-02 `확인 권장`, 유사 상표 목록·이름 바꾸기(후보)/그대로 진행. 이름을 바꾸면 상표 점검 결과가 바뀐다 |
| S3 | (마지막에 구현) 메뉴 설명에 효능 표현 | 프로토타입 미포함 |
| S4 | 문제없는 입력 | 문제 카드 없음. 영업신고 서류 안내·할 일·일정표만 |
| S5 | 마이페이지에서 주소·술 판매 변경 | 저장 전 미리보기 → 저장하면 영향받는 카드만 결정 대기로 복귀. 개업일만 바꾸면 날짜만 변경 |
| S6 | 계정 전환 | 다른 계정으로 로그인하면 가게·결과·체크리스트가 섞이지 않는다 |
| S7 | 서류함 열기 | 항목별 필요 서류·받는 곳 링크·찾는 방법·기관 전화번호, 완료한 항목의 서류 수 |

**수용 기준 (요약)**
- 모든 리포트 항목에 근거가 있다. 근거가 없으면 `판단 불가`다.
- 선택지의 기간·금액은 근거 없이 숫자로 나오지 않는다 ("확인 필요").
- 전화번호와 서류 링크는 AI가 만들지 않는다. 확인하지 못한 번호는 "예시" 배지.
- 선택을 되돌리면 그 선택으로 생긴 체크리스트 항목과 자동 체크만 풀린다.
- 상담의 변경 제안은 확인 전에는 반영되지 않는다.
- 어떤 외부 API가 실패해도 "예시 계정"은 끝까지 동작한다.
